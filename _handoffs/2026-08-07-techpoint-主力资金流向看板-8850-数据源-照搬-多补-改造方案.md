# 技术点 · 主力资金流向看板（8850）数据源「照搬 + 多补」改造方案

> 对应项目轴 Handoff：`2026-08-07-handoff-主力资金流向看板-8850-数据源-照搬-多补-改造方案.md`
> 目的：抽出「把一个外部动态看板改成可本地常驻、且多源冗余降级」这条链路里的**可复用技术资产**——同源代理绕开风控与跨域、子域探测方法论、双栈监听、浏览器回环绕过、favicon 内联、以及降级链设计。下次做「本地化外部看板 / 多数据源看板」可直接复用。

## 一、技术选型

| 选型项 | 选定 | 落选 | 依据 |
|---|---|---|---|
| 数据接入方式 | **同源代理（服务端出网 + 前端走 `host:""`）** | 前端直连东财 | 浏览器直连受跨域限制 + 风控；且前端直连会把密钥/行为暴露给外部（T1 实测） |
| 主数据源 host | **`push2delay.eastmoney.com`** | `push2` / `push2his` | 本机环境 `push2`/`push2his` 被应用层风控断流，**换子域后直连通**——判定「全封」是漏测子域的误判（T1） |
| 备用数据源 | **akshare 走 sina 系接口** | akshare 走东财 push2 系 | akshare 凡绕东财 push2 的接口全挂（ProxyError），走 sina 的直连可达（T1 逐个实测） |
| 监听栈 | **双栈（bind `::` + 关 `IPV6_V6ONLY`）** | 仅 IPv4 | 浏览器把 `127.0.0.1` 解析成 `::1`，只绑 IPv4 会转圈超时（T1） |
| 进程模型 | **`ThreadingTCPServer`** | 单线程 BaseHTTP | 多栏目并发请求下单线程会串行阻塞（T1） |
| favicon 交付 | **base64 内联 data URI** | 独立 `.svg` 文件引用 | 简易 python 静态服务给 `.svg` 返回 `application/octet-stream`，浏览器不渲染（T1） |
| 启动器编码 | **GBK + CRLF + 无 BOM，回显纯 ASCII** | UTF-8 / 带中文回显 | 中文 Windows cmd 下 UTF-8 无 BOM 在开头语法崩溃（T1） |

## 二、实施要点与关键技术

1. **判定「某接口全封」前先换子域测**：本机 `push2`/`push2his` 全挂，但 `push2delay` 全通——只测前两个就下「东财资金流被封」是实打实的误判。任何「流量被断」的结论，都先在同站其他子域上验证一次（T1）。
2. **同源代理关键三件套**：① 静态托管原版 `index.html`；② 加 `/api/qt/*` 路由转发到真实数据源（60s 缓存 + JSONP 透传）；③ 前端只改一处 `host:""` 走同源，**UI 一字不改**。这样保留原版观感，又绕开浏览器直连的一切跨域/风控问题（T1）。
3. **降级链按「同构源优先」设计**：主源 `push2delay` 挂 → 自动切 akshare 备用，且降级产物与主源**同构**（`{f12, f14, f62}` 形状一致），前端零改动即可渲染。分时 K 线没有等价备用源，做优雅降级（空图），**明确能力边界不硬凑**（T1）。
4. **双栈监听代码要点**：`server_address=('::', port)` + `sock.setsockopt(IPPROTO_IPV6, IPV6_V6ONLY, 0)`，同进程同时接 v4/v6，失败再回退纯 v4；配 `ThreadingTCPServer` 提并发（T1 实测验证 `[::]:8850` 与 `0.0.0.0:8850` 同 PID 双监听）。
5. **浏览器访问本地服务必须显式绕过系统代理**：用 `--no-proxy-server --proxy-bypass-list="*"` 打开页面（自动探测 Edge→Chrome→兜底 explorer）。否则 Clash 把回环请求截胡挂起，表现为「服务端一切正常但页面死转」。**排查「服务器正常、页面打不开」第一步先怀疑「浏览器→本地」这一跳**（T1）。
6. **favicon 内联避坑**：简易 python 静态服务对 `.svg` 返回 MIME 错误，浏览器不认；把 SVG 算成 base64 内联进 `<head>` 的 data URI 绕开 MIME 判定，100% 生效，同时保留 `favicon.svg` 源文件供预览。换图需让用户 Ctrl+F5 强刷（T1）。
7. **Windows 启动器要点**：端口预检 → 后台起 daemon（日志落 `logs/daemon.log`）→ 就绪轮询（`netstat` 确认 LISTENING 才开浏览器，避免竞态「连接被拒绝」）。回显文字全英文纯 ASCII，中文只出现在路径变量里（T1）。
8. **服务出网注意沙箱边界**：`app.py` 要代理外部数据源需 python 出网，而工具沙箱拦 python 出网（curl 不受限）。桌面双击 bat 由 explorer 交互会话拉起不受此限；在受限环境跑需显式放开沙箱（T1）。

## 三、模块职责划分

- **前端（静态 index.html）**：只负责渲染与交互，数据经同源 `/api/qt/*` 取，不直接触达外部域名。
- **本地代理（app.py）**：承担全部出网、缓存（60s）、JSONP 透传、主备降级、双栈监听。是把「外部动态看板」变成「本地常驻看板」的核心层。
- **主源 push2delay**：提供板块级与个股资金流主数据；断流时由代理层切备。
- **备用 akshare（sina 系）**：提供板块/概念/个股/沪深港通资金流的降级数据，形状对齐主源。
- **桌面启动器**：负责进程生命周期（拉起 + 就绪轮询 + 无代理开浏览器），与业务逻辑解耦。

## 四、如何选型（可复用的决策方法论）

- **「接口不通」先做三件事再下结论**：换同站子域测、走代理/直连各测一次、带/不带 cookie 各测一次。本项目「东财全封」是漏测子域造成的误判，三动作能避免。
- **数据源可用性判定粒度是 host，不是库**：同一个 AkShare，绕东财 push2 的接口全死、走 sina 的全活——选型时要按 host 分层记录，而不是笼统说「某库能不能用」。
- **降级设计先定「同构」目标**：备用源的输出形状必须和主源对齐，否则前端要写两套渲染。先有同构约定，再去找能满足形状的备用源。
- **本地化外部看板的标准套路**：不动原前端逻辑 + 加一层同源代理出网 + 启动器管生命周期。比「改写整个前端」稳且可逆。

## 六、技术结合点

- **同源代理 + 前端零改动**：代理层把「前端直连外部」改成「前端走本地」，前端 UI 一字不动就能本地化——这是整套方案可逆、可回滚的前提。
- **子域探测 + 降级链**：子域探测推翻了「东财全封」误判，才让 push2delay 成为主源；同构降级约定让 akshare 能无缝补位。探测结论直接就是降级链的入口。
- **双栈监听 + 浏览器代理绕过**：双栈解决「IPv6 解析」、代理绕过解决「Clash 截胡」，二者共同消除「服务器正常、页面打不开」这一类最迷惑人的故障。
- **favicon 内联 + 启动器就绪轮询**：两者都属「交付体验」层——内联保证图标一定显示，就绪轮询保证打开就可用。单独看是小点，合起来决定用户第一眼是不是「能开、能认」。
- **沙箱出网边界与启动器设计**：代理需 python 出网、沙箱拦 python，启动器走 explorer 交互会话绕开——生命周期方案的设计直接由沙箱边界决定，不是随意选择。
