# 技术点 · Hermes 8787 端口 MCP 连接失败 — 诊断（修正版 2026-08-15 16_27）

> 来源：handoff《Hermes 8787 端口 MCP 连接失败 — 诊断（修正版 2026-08-15 16_27）》（2026-08-15）

## 一、技术选型

- **系统**：Hermes AI Gateway / WebUI 双壳架构。
- **端口角色**：
  - `8787`：Python webui（`D:\hermes-webui\server.py`），只读展示 MCP 状态；
  - `8650`：Node webui（`npm 全局 hermes-web-ui`），持有 `POST /api/hermes/mcp/reload` 真正拉起 MCP；
  - `8642`：gateway/agent，实际 spawn MCP server 子进程。
- **涉及 MCP server**：`hermes-studio-api`、`browser`、`devices`、`use`、`playwright`。
- **认证方式**：8650 的 reload 端点走 `BearerAuth`，token 由启动后内存生成，外部 API 难以获取。

## 二、实施要点与关键技术

1. **先排除常见误判**：
   - venv 里 `requests`/`httpx` 已存在，不是缺依赖；
   - 8787 当前 err.log 为空，历史报错来自旧运行；
   - 三个端口都在监听，进程都在，问题不是「没启动」。
2. **真实症状**：5 个 MCP server `enabled=true` 但 `active=false`、`status="configured"`、`tool_count=0`。
3. **定位根因**：今天的 gateway（16:12 重启）没有自动 spawn MCP；`mcp-stderr.log` 最后一行停在 08-12。
4. **修复卡点**：8787 只有只读 API，真正能 reload 的 8650 端点需要浏览器 session token，curl 401。

## 三、模块职责划分

| 组件 | 职责 | 在本故障中表现 |
|---|---|---|
| 8787 Python webui | 展示 MCP 状态、切换 enabled | 只读，无法 spawn |
| 8650 Node webui | 提供 reload/start 能力 | 有接口但需 Bearer auth |
| 8642 gateway/agent | 实际 spawn MCP 子进程 | 重启后未触发 spawn |
| agent-bridge | 实现 `_mcp_reload` | 被 8650 调用 |
| MCP server 子进程 | hermes-studio / browser / playwright 等 | 全部未激活 |

## 四、如何选型（方法论）

- 遇到「MCP 无法连接」不要先猜依赖问题，要先查 `/api/mcp/servers` 看 `active` 和 `tool_count`。
- 区分「配置在」和「进程在」：配置在注册表里，进程在 tasklist 里，两者都要确认。
- 遇到 webui 认证卡死，优先走浏览器 UI 操作，而不是硬磕 API token。
- 日志要按时间切片：旧报错不能当作当前问题。

## 五、深化学习指引

- **Hermes 官方仓库**：需查看 `hermes-web-ui` 的 `index.js` / `bridge_server.py` 中 MCP 拉起逻辑（T0，本地源码）。
- **MCP 协议官方文档**：https://modelcontextprotocol.io/（T0）
- **Playwright MCP**：https://github.com/microsoft/playwright-mcp（T0）
- **故障排查 UP/博主**：YouTube/B站搜索「MCP server not connecting」「AI gateway MCP troubleshooting」，重点看如何读状态端点和日志。

## 六、技术结合点（1+1>2）

- **Hermes + Playwright MCP**：修复后可让 agent 直接调用浏览器截图、网页操作，打通「语言模型→浏览器」链路。
- **状态监控脚本**：写一个定时脚本 `curl http://127.0.0.1:8787/api/mcp/servers | jq`，若 `active=false` 则告警。
- **自动恢复**：研究 8650 启动时 `gateway-autostart` 的触发条件，做成「网关崩溃后自动拉起 MCP」的兜底。
- **诊断 SOP 复用**：「状态端点 → 进程列表 → 日志时间切片 → 认证/接口能力确认」四步法可用于任何 MCP/插件连接故障。
