# 技术点 · AI 赚钱商业机会研究（16 机会 + A/B/C 计划 + 9 项目 90 天路线图）

> 对应项目轴 Handoff：`2026-08-02-handoff-ai-赚钱商业机会研究-16-机会-a_b_c-计划-9-项目-90-天路线图.md`
> 目的：抽出「从零构造候选集 → 用数据证伪 → 多视角复审 → 收敛成排期」这套研究流程里的**可复用技术资产**——三套思维方法的编排方式、支撑结论的数据采集技术、以及「不编造证据」的取证纪律。下次做任何选题/选型研究都能直接复用。

## 一、技术选型

| 选型项 | 选定 | 落选 | 依据 |
|---|---|---|---|
| 方案生成方法 | **A 计划：六顶思考帽 + RACI + 红队击穿** | 单视角头脑风暴 | 单视角会漏掉「黑帽」（风险）与「红队」（主动证伪）两层，方案看着都可行 |
| 方案排期方法 | **B 计划：Cynefin 判域 + 看板 WIP + MoSCoW + 信号决策树** | 直接排甘特图 | 复杂域项目无法预排，只能定信号与决策点 |
| 方案验证方法 | **C 计划：PDCA 模拟跑批** | 拍脑袋定「哪个先做」 | 模拟能提前暴露「哪些只能当副线」，避免真金白银试错 |
| 证据基座 | **自建全量数据集（98,824 条唯一技能）** | 二手榜单/公众号数据 | 二手数据无法交叉验证、口径不明；自采可复算 |
| 采集架构 | **12 路并行（按分类分路）+ 错峰启动 + 断点续传 + 退避重试** | 单线程顺序抓 | 单线程耗时不可接受；无断点续传时中途失败全丢 |
| 采集礼貌策略 | 错峰 + 退避，不做循环重试 | 高并发轰炸 | 避免被判定为攻击，也避免制造假性限流数据 |
| 结论可信度标注 | **T0 官方 / T1 自测 / T2 印象级待核实** | 不标来源 | 研究类结论必须可追溯，否则复审时无法判断哪条能推翻 |
| 合规过滤位置 | **前置到筛选阶段（双过滤）** | 方案成型后再审 | 后置审查会导致整套方案推倒重来 |

## 二、实施要点与关键技术

1. **先证伪原始方法论，再谈新方案**。对现成的「三步法」逐条判定，得出「半真半假 / 操作上只能进红海 / 对无品牌小团队是伪命题」三种结论，并指出最大结构性漏洞：**三步全讲交付端，没有一步解决信任问题**。证伪先行，能避免在错误框架上叠加工作量（T1）。
2. **用可复算的硬数据推翻具体案例**。对「某品类定制」案例的否定依据是可验证事实链：相关企业绝大多数成立于一年内、原创产物三天内被大量店铺低价复制、多个实名亏损案例、且核心技术是成熟公开算法（有免费在线站与开放接口）→ 所谓 AI 壁垒不成立（T1）。
3. **接口层采集的关键三招**：目标站为前后端分离应用，真实接口匿名可读、每页固定条数；**按分类分路并行**（天然分片，无需协调）、**错峰启动**（避免瞬时峰值）、**每页落盘 + 记录游标**（断点续传）。最终去重得到 98,824 条（T1 实测）。
4. **数据结论要挑「反直觉且可行动」的**：全量库中仅约 1% 通过认证 → 「筛选/体检」类需求真实存在；按安装量分布可直接读出被验证的需求方向。这类结论比「市场很大」有用得多，因为它直接指向产品形态（T1）。
5. **合规双过滤的两条判定线**：① 转售或抓取再分发他人内容 = 侵权 + 违反服务条款，直接出局；② 只做索引、评论、推荐 + 自建产品 = 合规。这两条把 16 个候选一次性砍掉一批，且判定不需要个案讨论（T1 + 站点条款核实）。
6. **红线要按法条挂钩，不写模糊表述**：未授权 IP 定制（已有判赔判例，制作/销售方责任更重）；肖像权/人脸（《民法典》1019、《个保法》）；删除/篡改/隐匿 AI 标识（《标识办法》第十条 + GB 45438-2025）；平台站内引流私域（可永久封号）。每条红线对应一个具体来源（T0/T1）。
7. **采集到的数据要标注已知缺陷**：源站编码问题导致少量描述字段乱码，未重灌——**已知瑕疵要显式记录**，否则下游分析会把它当数据特征（T1）。
8. **写超长文档要分段追加**。一次性写入超长内容会静默失败，正确做法是先写骨架再分段追加，单次控制在约 6000 字符内（T1 实测踩坑）。

## 三、模块职责划分

- **A 计划（方案生成与击穿）**：负责「有哪些可能」与「哪些站不住」。产出候选集与否决规则，不负责排期。
- **B 计划（情境路由）**：负责「怎么排」。把抽象结论翻译成判域、优先级、并发度与决策信号。
- **C 计划（PDCA 验证）**：负责「先做哪个」。通过模拟给出核心线/副线的强制结论，是 A 与 B 之间的仲裁层。
- **数据采集层**：只负责获得可复算的原始事实，不做解释；结论层引用时必须带口径（去重前/后、采集时点）。
- **合规过滤层**：横切在筛选与复审两处，任何阶段都可否决，且否决优先级高于收益评估。
- **可信度标注层**：贯穿所有产出，每条关键结论挂 T0/T1/T2，使后续复审可以只针对低可信度项重跑。

## 四、如何选型（可复用的决策方法论）

- **三层方法各司其职，不要用一个方法通吃**：生成用发散型方法（多视角 + 红队），排期用情境型方法（判域 + 优先级 + 并发度），验证用闭环型方法（模拟 + 复盘）。混用会导致「排期时还在讨论要不要做」。
- **一票否决优先于加权打分**。加权打分会让「各项都还行但有致命缺陷」的方案排到前面；先用硬否决过滤，再对幸存者打分。
- **数据驱动选题的正确顺序**：先拿到可复算的全量数据 → 再从中读需求分布 → 最后用多视角方法生成方案。用数据做前提而非事后佐证，结论才经得起复审。
- **采集架构设计与「被当成攻击」是同一个问题**。并行分路 + 错峰 + 退避 + 不循环重试，既是礼貌也是数据质量保障——循环重试制造出的假性限流会让后续分析失真。
- **证据不足时标注 T2 并显式留待核实**，绝不补一个看着合理的数字。研究文档的可信度来自「每条结论都能追到来源等级」。

## 六、技术结合点

- **A 计划的「红队击穿」为 B 计划的「判域」提供输入**：被红队证伪的部分直接归入「不可行域」，剩下进 B 计划的复杂/混沌域判域，避免把该砍的也拿去排期。
- **B 计划的并发度（WIP≤2）为 C 计划的模拟设定边界**：模拟不需要在 16 个候选上全跑，只在 B 计划收敛出的核心线/副线条上跑，PDCA 的算力开销被前置方法压到最低。
- **全量数据集同时喂养「选题」与「合规过滤」**：同一个 98,824 条数据，既能读出需求分布，又能支撑「1% 认证率 → 体检类需求真实」的论证；数据层一次建成，多层结论复用，可复算性贯穿全程。
- **可信度标注串起整条链路**：A 生成时标注来源 → B 排期时只看高可信项 → C 模拟时优先验证低可信项 → 输出报告时每条结论自带 T 级。没有这层标注，多轮方法协作会退化成「谁声量大听谁的」。
- **合规双过滤是横切护栏**：它不属任何单计划，但在 A 生成、B 排期、C 验证三处都可触发否决，使「商业可行」与「合规可行」成为两个独立闸门而非一个加权项。
