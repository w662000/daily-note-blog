- 原"轻量：经 8787 webui API 触发 spawn"方案 **前提不成立**（已证伪）：

    `PUT /api/mcp/servers/{name}`（改 config）。**没有任何端点会真正 spawn MCP 子进程**。
  - routes.py 里也**没有 `/reload-mcp` 端点**。
- 真正能重新拉起 MCP 的是 **8650 壳**的 `POST /api/hermes/mcp/reload`
  （openapi.json:7684；由 `agent-bridge/python/bridge_server.py:_mcp_reload` 实现：

- 但该端点 **强制 `BearerAuth`，curl 侧无法取得正确 token**：
  - 试 `.hermes-web-ui/.token`（64hex）作为 `Bearer` → **401 Unauthorized**；

  - 8650 进程命令行无 `--token` 参数；index.js 仅有 `EKKO_CODE_RPC_TOKEN`（ekko RPC 用，非 webui Bearer）。
  - 结论：该 Bearer 是 8650 启动后内存随机生成、只认浏览器 session，**API 这条路被 auth 卡死**。
- server.log 旁证：8650 启动会 `gateway-autostart` + 拉起 agent-bridge；当前实例的 MCP 子进程未起来，
  与"今天网关没自动 spawn MCP"一致。
