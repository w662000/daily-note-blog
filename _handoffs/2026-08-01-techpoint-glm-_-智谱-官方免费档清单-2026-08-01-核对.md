# 技术点 · 模型「免费档」核实方法与多模型清单治理

> 对应项目轴 Handoff：`2026-08-01-handoff-glm-_-智谱-官方免费档清单-2026-08-01-核对.md`
> 目的：从该项目提炼**可复用技术资产**——如何区分"平台免费档"与"账户赠送额度"、如何用实测数据而非宣传口径给模型分档、模型清单（models.json）该怎么维护。下次接任何一家大模型厂商的免费资源，直接复用这套核实流程。

## 二、实施要点与关键技术

1. **"免费档"≠"赠送额度"，两者必须在清单里分开标。**
   - 免费档 = 平台侧标注"免费模型"，不消耗 token，可长期使用；
   - 赠送额度 = 付费模型被资源包/赠送额度覆盖，额度耗尽即报错。
   实测暴露过一次：8 个标"赠送"的 GLM 条目返回 HTTP 429，但响应体业务码是 `1113 余额不足`——在客户端选中会直接报错，此前完全不知情（T1）。

2. **HTTP 状态码不够用，必须解析响应体 `error.code` 做二次分类。**
   实测归纳的 GLM 错误码分档（T1）：

   | 业务码 | 含义 | 重试有用吗 |
   |---|---|---|
   | `1113` / `1112` / `1261` | 无额度 | ❌ 重试无效，只能充值 |
   | `1305` / `1302` / `1303` / `1304` | 真限流 | ✅ 退避后可重试 |

   第一版代码把 `1113` 一刀切当限流，导致无限重试白烧配额；改成解析 `error.code` 分类后才正确。

3. **免费档首包可能比付费高并发档更快。** 同一问题下 `glm-4.1v-thinking-flash`（免费）TTFT 466 ms，`glm-4.1v-thinking-flashx`（付费高并发，2 元/百万 tok）TTFT 1476 ms。推测免费档边缘节点/缓存更热（T2 待核实，仅单次样本）。**代价在并发上限**：Flash 免费档 V0 仅 5 并发，FlashX 高并发档 V0 = 30。→ **低并发个人场景优先免费档，高并发生产才买付费档。**

4. **命名相似的付费/免费模型要在显示名上强制区分。** `glm-4.6v-flash`（9B）永久免费不扣额度，`glm-4.6v`（106B）付费扣资源包，名字只差一个后缀。做法：把付费那个显示名改成 `GLM-4.6V (付费)`，只改 name 不动 model id（T1）。

5. **客户端字段名要按"踩坑实测文"核实，不是按接口文档。** 报 `400 max_tokens 参数非法：限制数值范围[1,16384]` 时，先按官方 API 文档加了 `maxOutputTokens` → 无效；实际客户端读的是 `maxTokens`（驼峰单数）。教训：查"某字段在客户端里是否生效"，接口定义类文档不管用，要找报错修复贴（T1）。

6. **上下文溢出无法靠配置解决。** 修完字段名后新错误变成 `inputs tokens + max_new_tokens must be <= 65536. Given: 90196 inputs tokens`——`glm-4.1v` 的**总上下文只有 65536**（不是"输入 65536 + 输出 16384"），`maxInputTokens` 只是显示字段不是截断开关。唯一解法是开新会话，或换 128K 上下文的模型（T1）。

7. **换 key 后不要为"全面验证"去循环打接口。** 换 key 后只单枪直连验一个模型返回 200，其余交给后续定时轮次自然解冷却，不为刷绿看板轰 API（T1）。

## 三、模块职责划分

- **模型清单（models.json）= 唯一事实源**：只记录"这个模型在本环境能不能用、什么档、什么能力"，是所有下游（客户端选择器、测速探针、路由）的输入。
- **官方文档/定价页 = 外部权威源**：决定"这个档是不是真免费"，只读、不可推断。
- **实测探针 = 现实校验层**：决定"官方说有 ≠ 我这儿能调通"。三者中任何一个单独都不可信。
- **错误码分类器 = 探针与清单之间的翻译层**：把 HTTP 层信号（429/400/404）翻译成业务语义（无额度/限流/参数错/端点不符），清单只吃翻译后的结论。

## 四、如何选型（可复用的决策方法论）

- **免费资源盘点三步**：① 官方定价页筛"免费"标签 → ② 官方模型概览页确认上下文与能力 → ③ 单发实测确认端点真通。三步缺一步就会把已下线的废档写进清单。
- **判断一个"免费"是否真免费**：看它耗不耗 token 配额。耗配额的都是"被额度覆盖的付费模型"，额度一断就废。
- **同系列多档位怎么挑**：先看上下文（够不够装你的会话）→ 再看是否强制 CoT（强制 CoT 会拖总耗时）→ 再看是否支持工具调用（agent 场景必需）→ 最后才比首包延迟。
- **遇到官方已知缺陷的模型直接换代**：厂商 README 里公开承认的 bug（如 overthink / repeat / 字符转义损坏）不会靠调参解决，找同系列下一代的免费档替代。
- **并发上限是隐藏成本**：免费档往往并发极低（5 vs 30）。个人/低频场景吃免费档收益最大；批量任务要提前算并发预算。

## 六、技术结合点

- **错误码分类器 + 清单标注**：只有先把"无额度"和"限流"分开，清单里的"赠送"标记才有意义——否则一堆看着能用实际报错的条目会污染整个选择器。
- **官方文档 + 单发实测**：官方说"有"、实测说"通"，两者同时成立才写进清单。只信任一边，要么漏掉可用模型，要么把废档当宝。
- **首包指标 + 并发上限**：单看首包会得出"免费档比付费档还快、付费毫无意义"的错误结论；配上并发上限才能得出正确结论——**免费档赢在低并发时的调度优先级，付费档赢在吞吐**。
- **显示名治理 + 能力字段**：改显示名（加"付费"后缀）解决人为误点，能力字段解决程序误选，两层一起做才防得住"名字太像"这类事故。
