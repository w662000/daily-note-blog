# WB ↔ AutoClaw 双向 Agent 协同系统 · 总览与部署说明

- **日期**：2026-10-04
- **状态**：✅ 已完结（scan 自动收集）

> 来源：基于豆包对话《GitHub Agent 能力复用 + WB↔AutoClaw 协同设计》落地执行。
> 目标：**去掉你手动在 WB 和 Claw 之间复制 MD 的中转**，让两个 Agent 自动多轮互审，直到双方共识，再交付最终方案。

## 一、为什么要这套系统
你原来的流程：WB 出方案 MD → 你手动发给 Claw → Claw 改意见出 MD → 你手动发回 WB → 多轮 → 双方认可后执行。
痛点：人工复制粘贴、人工判断轮次终止、上下文容易丢。

本系统用「**协同调度器**」替代你的人工中转：它是状态机 + 消息转发逻辑（不是另一个大模型），自动把 WB 的方案转给 Claw 评审、把评审意见转回 WB 修改，直到 Claw 给出【可通过】或达到最大轮次。

## 二、角色分工（固定，不可互换）
| 角色 | 模型 | 职责 |
|---|---|---|
| **WB（提案方）** | hy3 / hy4preview | 接需求 → 出 MD 方案 V1 → 收评审 → 迭代 V2… → 判是否满足 |
| **AutoClaw（评审方）** | GLM 5.2~5.3 | 收 MD → 启动「轮子优先 Skill」核验 → 出结构化评审 + 【可通过/需迭代】 |
| **调度器** | 顶层控制器 | 状态机 + 消息转发 + 轮次计数 + 终止汇总 |

## 三、数据流
```
用户需求 → 调度器 → WB(V1) → 调度器 → AutoClaw 评审
   ├─【需迭代】→ 评审原文 → 调度器 → WB(V2) → 调度器 → AutoClaw … 循环
   └─【可通过】/ 达上限 → 调度器输出 定稿 + 全过程日志 + 未决分歧
```

## 五、部署方式（两种）
**方式 A：OpenClaw 内实现（推荐，贴合你现有环境）**
1. 在 OpenClaw 注册 2 个 Skill：`WB-AutoClaw-Coordinator`（调度器）绑定 `01` 文件；`Wheel-First-Solver` 绑定你已创建的 `agent-capability-reuse` 技能（WB 侧也建议装，见 `~/.workbuddy/skills/agent-capability-reuse/`）。
2. 调度器作为顶层 Agent，调用 WB 模型接口 + 本地 GLM 实例，维护会话上下文，自动转发。
3. 真实配置参考（已核实）：AutoClaw 模型源在 `C:\Users\Administrator\AppData\Roaming\autoclaw\settings.json` 的 `models.catalog`；`openclaw.json` 是其产物。技能/模型导入以官方机制为准。

**方式 B：简易原型（快速验证）**
把 `01` 调度器提示词作为顶层总控制器一次性粘贴，让它来回调用 WB / AutoClaw。适合先验证协同效果，再正式化。

## 六、边界与优化点
1. **上下文溢出**：长方案多轮 token 暴涨。可选策略：调度器只传「变更 diff」而非全文。
2. **角色污染**：严格隔离——WB 不检索评审，Claw 不直接重写方案。
3. **环境约束**：评审环节强制检查便携/离线相关（相对路径、不写死 C 盘、可离线、加密）。
4. **分歧处理**：达上限仍不共识 → 单独列分歧交你人工裁决，禁止 Agent 强行妥协出错误方案。
