# 技术点 · 2026-08-05

## 一、涉及的项目 / 主题

- 联想 N50-80 双系统部署（Win10 + Debian + Hermes 共享）
- 双系统数据互通方案设计
- 老机器选型与系统轻量化

## 二、关键技术点

1. **老机器选 Debian 不选 Ubuntu 的原因**：Ubuntu 默认带 snapd，系统开销更大；Debian minimal 更轻，对 4GB 内存 + 5 代低压双核更友好。来源：handoff「联想 N50-80 双系统部署」。

2. **双系统安装顺序不能反**：必须先装 Windows，再装 Debian。后装 Debian 时 grub 会自动识别 Windows 并加入启动菜单；反过来 Windows 会覆盖 grub 导致 Debian 无法引导。来源：handoff「联想 N50-80 双系统部署」。

3. **Hermes 数据共享的正确姿势**：不能把整个 `~/.hermes` 或 `%LOCALAPPDATA%\hermes` 软链到共享盘，因为两边安装器都会往 `hermes-agent/` 写代码，互相覆盖会导致启动崩溃。正确做法：**代码各自留在系统盘，只把数据子目录（sessions/skills/memory/config）的真身放共享盘，两边建软链指过去**。来源：handoff「联想 N50-80 双系统部署」。

4. **Windows 快速启动必须关闭**：不关的话 Win 关机其实是休眠，NTFS 卷被锁，Debian 挂载时只能只读，Hermes 写不进数据整个方案就废了。来源：handoff「联想 N50-80 双系统部署」。

5. **NTFS 在 Debian 下挂载必须带 `uid=1000,gid=1000`**：否则 Hermes 因权限不足读不了配置。fstab 里用 `LABEL=SHARED` 比 `/dev/sda4` 更稳（设备名可能变）。来源：handoff「联想 N50-80 双系统部署」。

6. **Win7 不可行**：Node 18 和 Python 3.10 起不再支持 Win7，且 Hermes 安装器需要这些版本。老机器必须选 Win10 而非 Win7。来源：handoff「联想 N50-80 双系统部署」。

7. **一次只启一个系统**：双系统同时挂同一 Hermes SQLite 库会导致数据库锁。所以这套方案天然适合"切换使用"而非"同时运行"。来源：handoff「联想 N50-80 双系统部署」。

## 三、值得记的教训

- 做跨系统共享方案时，先区分"代码"和"数据"，代码各平台独立、数据可共享，否则安装器的平台差异会把共享目录冲烂。
- 系统安装顺序是"硬规则"不是"建议"，先 Linux 后 Windows 的代价是重新修引导。
- 老机器跑 agent 只能走"调远程 API"路线，4GB 内存 + 低压双核本地跑大模型不现实。
- 分区要给 EFI 留 512MB，扣掉之后实际可用空间比直觉少，规划时不能忽略。
- 共享盘格式选 NTFS 而非 exFAT，虽然 exFAT 也能双系统读写，但 NTFS 有权限控制（`uid/gid`）更适配 Linux 用户体系。
