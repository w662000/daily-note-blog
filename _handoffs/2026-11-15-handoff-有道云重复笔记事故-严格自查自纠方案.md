## 一、事故一句话定性

**"幂等假设未经验证 + 外部接口行为与假设不符 + 失败模式是多存不是报错"** 三者叠加，被每天 1~2 次的高频调度放大三个月：查重函数只读了有道云 list 的第一页（50 条），素材涨过 50 条后所有旧笔记被误判为"新笔记"每天重发；CLI 遇到同名不报错、静默加 `(n)` 后缀再存一份；SUMMARY 始终全绿（"82 篇，成功 81"），三个月 0 告警。

## 二、完整根因链（五层失效，每层都是独立防线，全部失守）

| # | 层 | 失效内容 | 证据 |

| ① | 查重数据源 | `run_list()` 单次调用只读 list 第一页 ~50 条，无分页；素材 >50 条后第 51 条起的旧笔记永远不在查重集合 | `list --help` 实锤有 `-l` 游标分页；worklog 第一页恰好 50 条 |

**关键教训**：代码逻辑没有 bug，是它**依赖的外部接口行为**（分页 + 延迟）与**假设**不符；且失败模式是"多存"而非"报错"——这类组合是最危险的静默污染。

## 五、写入门禁制度（本次事故的制度化产物，以后同类项目强制执行）

**适用范围**：任何向**外部存储系统**（云笔记/云盘/数据库/论坛/博客远端/第三方 API）做**可重复触发的写入**的项目，凡自称"幂等 / 已存在则跳过 / 查重"的，上线前必须过 **G1~G5 五道闸门**，缺一不许上线。

### G1 数据源完备性闸门（最关键，本次事故主因）

> 查重依赖的 list/search 数据源，必须**证明**它返回的是全量，而不是"假设"它是全量。

- 分页处理：拉到游标尽头，不能用"单次调用"当全量；
- 延迟处理：刚写入的数据立即查可能查不到——要么等，要么换全库 search，要么以写入回执 ID 为准；
- **验证方法（一次 planted-count 测试）**：向目录预置已知数量 N 条（或用已有目录的已知计数），断言查重函数能读到 ≥N；读不到就拒绝运行写入。
- 通过标准：`assert len(dedup_source) >= planted_count`。

### G2 静默失败探针闸门

> "重复写入会报错"必须实测，不能靠文档想象。

- 在沙盒目录**故意存两次同名笔记**，观察返回：报错 → 幂等可信；静默改名/静默覆盖 → 该系统不能靠"重复报错"兜底，查重必须前置且完备（G1 升级为硬性）。
- 通过标准：探针结论写入项目 README，明确标注该外部系统属于哪种失败模式。

### G3 写入规模熔断闸门

> 每次运行先声明 `expected_write_count`（本次预期写入条数），运行结束时核对。

- 实际成功数 > 预期 × 1.5（或超过绝对上限）→ **立即熔断**：中止后续写入、不退出成功、报警并冻结任务；
- 本次事故若有此闸：每次"82 篇成功"vs 预期 1~3 篇 → 第一天就会熔断，事故根本存续不了 120 天。

### G4 台账闸门

> 每一次创建/删除的 ID 必须落台账（ID + 标题 + 时间戳 + 触发来源），本地 JSON/SQLite 均可。

- 用途：精确回滚、损害量化、对账基准；
- 本次 81 篇能精确删除，靠的就是 `youdao_upload.log` 的 81 行 `[OK]` ——这是侥幸（日志格式没设计过当台账用），必须变成设计。

### G5 周期对账闸门

> 定时（每周）只读审计：远端目录实际条数 vs 台账预期条数。

- 偏差 > 阈值（如 >10 条或 >5%）→ 告警 + 冻结该链路写入，人工核查后解冻；
- 实现方式：挂到现有计划任务体系（pythonw 无窗口，参照 `win-py-daemon-launcher` 铁律）。

### AI 行为守则（附加，非代码闸门）

1. **禁止用全量同步当调试手段**——查 exit 码原因先读代码读日志；
2. 注释/文档不是证据，**行为必须实测**（G2 探针就是为此存在）；
3. 审计类只读操作也要看清数据边界（分页/排序/条数上限），避免误报漏报；
4. 一切 subprocess 外部调用必须带 `CREATE_NO_WINDOW`（已有红线，此处重申关联）。

## 六、事故响应流程（SOP，发现同类污染时按序执行）

1. **冻结写入**：第一时间停写入口（暂停 automation / 结束进程），防止损害扩大；
2. **保底账**：只读盘点远端全量（分页翻页 + 每 N 页落盘），产出 ID 清单；
3. **定根因**：用证据链定位哪层失效（G1~G5 哪个闸门缺失），未查明前不删任何数据；
4. **量化损害**：精确副本数/污染范围，向用户报数再动手（外部数据删除前必须报规模）；
5. **修复顺序固定**：防复发代码修复 → 数据清理 → 回归探针（G2 重测）→ 制度化（G1~G5 落地 + skill 固化）；
6. **复盘落盘**：事故文档 + 长期记忆 + skill 更新，三处齐做。
