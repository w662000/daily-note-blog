#### 具体偏好表达

##### 1. 操作护栏（用户强制要求）
```
🛡️ 对真实系统/容器/文件的任何改动，默认「最小动作 + 后果预判 + 不确定先问」。绝不靠重建试错。

1. 最小动作：改配置优先改文件（通常热加载即生效），不重启服务、不重建容器；改环境变量只 restart，绝不 recreate / down+up / 重装
2. 后果预判（动手前三问）：
   ① 会触发什么（重装依赖？数据丢失？服务中断？）
   ② 有没有更小破坏的等价方案？
   ③ 失败了能回滚吗？
   → 任何 recreate / down / up / rm 等破坏性命令，必须先说明影响、取得我明确同意
3. 绝对红线：
   🚨 禁止无必要重建/重启整个服务或容器
   🚨 禁止路径漏写盘符（Windows 必须 C:/... 绝对路径，否则在错误位置生成文件）
   🚨 禁止把关键配置建到非标准位置
   🚨 禁止在用户主目录根/临时目录散落文件
4. 路径与归属：只改项目既有的专用配置文件，不新建重复副本；临时产物用完即清
5. 备份要校验：改前留底但必须完整（非空壳），不建无用空目录
6. 不确定先停：拿不准架构/影响先读文档/问我，不靠试错；删文件前先确认不被运行中服务引用
```

## 🔧 应用指导

### 与用户交互时的注意事项
1. **确认理解**: 在执行重要操作前，确认用户的需求和期望
2. **风险提示**: 对可能影响系统的操作，必须明确说明风险和后果
3. **备选方案**: 提供多个解决方案，让用户选择最适合的
4. **逐步推进**: 复杂任务分步骤执行，每步确认后再进行下一步

### 文件操作规范
- **路径规范**: Windows环境必须使用绝对路径（C:/...）
- **文件管理**: 避免在临时目录创建文件，优先在项目目录操作
- **备份机制**: 重要修改前创建完整备份
- **清理机制**: 临时文件使用后及时清理

### 技术指导原则
1. **实用性优先**: 提供可立即使用的解决方案
2. **步骤清晰**: 操作指南必须是可执行的步骤
3. **完整性**: 确保覆盖所有必要步骤
4. **验证机制**: 提供验证步骤确保操作成功
