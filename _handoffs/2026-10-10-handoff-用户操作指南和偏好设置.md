# 用户操作指南和偏好设置

## 🎯 技能概述

本技能基于与用户的实际对话，记录用户的操作护栏、工作流程偏好和实用指导原则。这些是从用户直接表达的需求和偏好中提取的，确保未来的交互更加符合用户的期望和工作风格。

## 📋 核心用户偏好

### 用户身份和工作风格
- **用户角色**: Hermes新手，偏好循序渐进的学习方式
- **工作风格**: 分阶段、有计划的学习和实践导向
- **时间安排**: 上午安装配置，下午学习TDD，晚上实践架构图
- **学习目标**: 先部署再学习，重视实际应用场景

### 操作护栏（用户强制要求，最高优先级）
对真实系统/容器/文件的任何改动，默认「最小动作 + 后果预判 + 不确定先问」。绝不靠重建试错。

#### 🛡️ 核心原则
1. **最小动作**: 改配置优先改文件（通常热加载即生效），不重启服务、不重建容器；改环境变量只 restart，绝不 recreate / down+up / 重装
2. **后果预判**: 动手前三问：① 会触发什么（重装依赖？数据丢失？服务中断？）② 有没有更小破坏的等价方案？③ 失败了能回滚吗？→ 任何 recreate / down / up / rm 等破坏性命令，必须先说明影响、取得用户明确同意
3. **绝对红线**: 🚨 禁止无必要重建/重启整个服务或容器；禁止路径漏写盘符（Windows 必须 C:/... 绝对路径，否则在错误位置生成文件）；禁止把关键配置建到非标准位置；禁止在用户主目录根/临时目录散落文件
4. **路径与归属**: 只改项目既有的专用配置文件，不新建重复副本；临时产物用完即清
5. **备份要校验**: 改前留底但必须完整（非空壳），不建无用空目录
6. **不确定先停**: 拿不准架构/影响先读文档/问我，不靠试错；删文件前先确认不被运行中服务引用

### 文件格式偏好
- **Markdown文档**：直接在回复中展示内容，不要使用 `MEDIA:` 前缀（会导致弹出保存对话框）
- 可使用普通markdown链接 `[文本](路径)` 格式
- 文件路径使用绝对路径，Windows用正斜杠 `D:/path`
- **工作区文档组织**：按日期创建文件夹，格式 `YYYYMMDD`（如 `20260809`），每天的工作文档归类到当日文件夹。当前工作区根目录为 `D:/hermes-studio/`，每日文件夹如 `D:/hermes-studio/20260809/memory.md`
- **参考文档**：详见 `references/workbuddy-worklog-generation.md` 了解工作日志生成方法
- **平台架构参考**：详见 `references/hermes-platform-architecture.md` 了解 Hermes Studio / WebUI / Agent 三层架构对比

### Windows 配置编码注意
- **Hermes config.yaml 中文 label 风险**: 在 Windows 环境下，`config.yaml` 中的中文 label 容易变成乱码 mojibake，影响模型列表可读性。
- **修复方式**: 用 Python 读取 `errors='replace'` 后批量替换乱码 label 为英文说明；不要直接反复 patch 安全敏感配置文件，工具会被拒绝。
- **预防**: 新增模型 label 时尽量使用纯英文，避免中文导致跨平台编码问题。

### 信息处理偏好
- **偏好实用**: 重视实际应用场景，重视可视化工具和系统化学习路径
- **学习方式**: 实践导向的学习，希望先部署再学习
- **内容要求**: 详细的部署指南和实践任务
- **格式偏好**: 清晰的步骤说明和可执行的操作指南
- **实证优先**: 用户对泛泛而谈/猜测性回答很敏感。当被要求比较产品或评估能力时，必须先用工具实测（curl探活、API文档查询、MCP openapi_get等）拿到真实数据，再给出基于事实的比较。禁止凭印象编造功能对比表。用户说"越详细越好"时，意味着需要更深的实测数据，不是更多猜测性文字。
- **停止条件**: 当用户说"已有配置"、"workbuddy已配置好"、"不要瞎改"等表达时，立即停止提出新的配置/修复/安装方案。此时应先验证当前状态，再决定是否需要最小动作修正，而不是继续建议替代方案。

### 技术偏好
- **模型选择**: 对GLM模型有具体使用场景要求，需要清晰trade-offs和具体推荐
- **工作流程**: GitHub-based部署工作流，copy-pasteable的Dockerfiles和部署脚本
- **工具使用**: 偏好GitHub-based部署工作流，重视实际操作指导
- **升级前确认**: "升级"可能指核心 agent、web UI 外壳、desktop 壳层等多个对象；执行前必须先确认目标项目/版本/来源，不要默认按升级 agent 处理。拿不准时先搜索，再执行；禁止凭印象猜版本和路径。

### Hermes 操作偏好
- **WebUI 优先**: Windows 环境下优先使用 WebUI（hermes dashboard）而非 Desktop，因为 Desktop 构建复杂且易出问题
- **命令行操作**: 熟练使用 terminal、file、code_execution 等工具进行命令行操作
- **技能管理**: 重视技能系统的学习和使用，按照学习计划分阶段掌握
- **文档输出**: 生成详细的技术文档和参考指南，便于后续查阅

### Windows文件系统操作规范
- **路径格式**: Windows环境支持多种路径格式（`C:\\path`、`/c/path`、`D:/path`），优先使用正斜杠格式 `D:/path` 并加双引号 `"D:/path"`
- **权限处理**: 即使有管理员权限，某些系统目录可能仍需特殊处理，遇到访问失败时提供多种解决策略
- **工具兼容性**: 不同工具在Windows上的行为可能不一致，需要备用方案
- **错误处理**: 文件访问失败时提供多种解决策略，包括手动文件传输
- **文件系统访问失败处理**: 当 `terminal`、`read_file`、`execute_code` 等工具因路径问题失败时：
  1. 检查路径格式（使用正斜杠 `/`）
  2. 用双引号包围路径 `"D:/path"`
  3. 确认目录存在和权限
  4. 尝试不同的工作目录
  5. 最后考虑手动文件复制作为备用方案
- **参考文档**: 详见 `references/windows-filesystem-troubleshooting.md` 获取详细的故障排除指南
