### 第二个真 bug：信用表有第三个区块

把真实 `orchestrator models` 输出落盘成 fixture 后立刻发现：真实表是三段，不是两段。

```
--- credits = x0.00 (0 积分) ---                              free（3）
--- billed models (x>0) ---                                   billed（20）
--- unlabeled credits=null (100, bridge custom providers) --- 第三段（100 个）
```

`parseCreditTable` 只认前两个 banner，于是第三段开始时 `section` 仍是 'billed'，100 个 `custom-local:*` / `default-model` 全部漏进 billedModels：

- billed 计数 20 → 123（面板计数虚高）；
- 计费护栏会误拒钉在"积分未知"自定义模型上的 judge peer（fail-closed 打错方向）。

修法：任何未被识别的 `--- … ---` banner 关闭当前区块（未来 CLI 加段也不会泄漏）。回归断言：`custom-local:*` 不得出现在 billed、billed < 60。烟测同步加"实时信用表解析"检查 → 20/20。

**教训：解析外部 CLI 输出，必须用真实抓取做 fixture，不能只靠自造的假样本。**

### 第三个真 bug：taskkill 同步且慢

偶发 `not ok 167 - a timeout is flagged and the process is reaped`（tests/spawn.test.mjs，等待 26.8s，断言 `< 25s` 失败）。

**根因不是测试写错，是产品代码**：`killTree()` 用 `execFileSync('taskkill',['/PID',pid,'/T','/F'])`，而 `execFileSync` 阻塞事件循环。实测本机：空闲 3251 ms；全量并行负载 ~25 s。

→ 生产后果：成员超时 / reapAll 时 MCP server 事件循环被卡住（HTTP、scheduler tick 全停）。

修法：`execFileSync` 加 `timeout: 8000` 硬上限（超时则回退 `process.kill(SIGKILL)` 杀直接子进程）。测试判据同时改为"子进程睡 60s、上界 30s"。单跑该用例 6.8s。

- **P1.2「坏 `--orchestrator-config` 会让 MCP server 崩溃」→ 前提不成立。** 实测：`loadConfig` 不做 I/O；`loadPeerConfig` 读/解析失败 try-catch 返回 null；`runAsync` 只 resolve 不 throw；`startServer` 正常启动并干净关闭。全链路无一处 THREW。
- **P1.4「git stderr 被丢弃」→ 已实现。** `gitStatus()` 已把 stderr 首行写进 `reason`，`runDeliveryAudit` 又把 `reason` 落进 `audit.json`。审计建议的 `gitDiagnostic` 字段与既有 `reason` 重复。
- **P1.2 的"拒绝启动"部分 → 主动不做**：评审是 best-effort，server 主职责是 15 个团队/成员工具（不需要 peer）。为一个评审侧配置错误把整个连接器弄挂是更糟的失败模式。

### 确有必要（已落地）

1. **真 bug：`tail()` 只取 stderr 最后 4 行 → 错误信息被丢。** 真实 orchestrator 的输出是「1 行有用信息 + 一大段 ESM 堆栈」，旧 `tail()` 只留 `at ModuleJob.run (node:internal/…)`，路径不见了。改为优先保留首部非堆栈行（`^at ` / `^node:internal/` / 分隔线视为噪声）。
2. **P1.1 探针重试日志**：`probeReady` 原来静默重试 —— "抖动后恢复"与"一次成功"在结果上完全一样。现在每次失败一条 `[peer-probe] WARN … n/N`；ECONNREFUSED 单条且不重试；全败打 `treating … as down`；惰性拉起每 10s 一条进度（实测就绪 23-26s，没这条日志看着像挂死）。
3. **P1.2/P1.6 路径配置启动校验**：新增 `validateOrchestratorConfig()`（纯函数+FS），三种坏法（不存在/非 JSON/无 peers）→ `[config] ERROR 完整路径`，并进 `agent_teams_status.configIssues`。**不拒绝启动**。
4. **P1.5 foreign 拒绝给可复制命令**：新增 `killHint(pid)`（win32 `taskkill /PID n /T /F`，其它 `kill n`）。
5. **P1.3 模型目录降级可见**：`readCache` 区分「没有缓存」与「缓存过期」；过期后冷探失败/刷新被关 → `[model-catalog] WARN` + `modelsDegraded/modelsNote`。过期缓存不再被当当前列表用。
6. **文档 3 处**：① pipeline 表述自相矛盾统一；② 测试命令补注"单测不拉真实 CLI"；③ 新增「MCP 重启后自己拉起的 peer 会变成 foreign」已知现象节。
