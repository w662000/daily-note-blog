## TradingAgents-CN 故障修复（服务反复崩溃 + 任务全失败）

用户反馈"昨天部署的系统还有错误"，排查发现 4 个叠加问题：

### 1. WSL systemd 反复崩溃（根因）
- 现象：内核 uptime 39 分钟不变，但 systemd (PID 1) 每 1-3 分钟重启一次（apport socket 反复 Closed/Listening），所有服务跟着被杀重启 → 8000 端口时有时无、任务中断
- 元凶：`wsl-pro.service`（Ubuntu Pro 桥接服务）因 interop 问题持续失败（exec format error 调 cmd.exe），NRestarts 一路涨到 8+，每 2 秒循环一次拖垮 systemd
- 修复：`systemctl disable --now wsl-pro.service` → PID 1 elapsed 稳定增长，不再崩溃

### 2. 双套服务进程抢端口
- 昨天部署时配了 cron `@reboot /root/tacn-watchdog.sh`（每 60 秒检查端口、nohup 拉起）+ systemd enable 自启 → 两套 uvicorn/worker/vite 抢 8000/3000
- 修复：crontab -r 清除 watchdog（脚本已备份 tacn-watchdog.sh.bak-20260812），保留 systemd 单一管理
- 新增 tacn_killall.sh 清理脚本备用

### 3. sensenova key 额度用尽（任务失败的直接原因）
- POST token.sensenova.cn/v1/chat/completions → 429 insufficient_quota（"Allocated quota exceeded"）
- 4 个 provider 实测：sensenova 429 欠费 / agnes OK / stepfun OK / glm OK
- 修复：system_configs version 8→9，sensenova enabled=false（保留记录），agnes priority=10→100，调度脚本模型 deepseek-v4-flash → agnes-2.5-flash
- 验证：600519 全流程 completed（355 秒），报告：卖出/目标价1256/置信0.8，model_info=agnes-2.5-flash

### 4. 数据源降级（不影响主流程）
- BaoStock 被封"黑名单用户"（昨频繁登录触发），股票信息/财务数据走 akshare（同步 5543 条成功）
- akshare 新闻接口报 "Invalid regular expression: invalid escape sequence: \u"（东财新闻正则 bug），FinnHub key 还是占位符 your_finnhub..._here
- sensenova embeddings 404 → 记忆降级空向量

## 13:05 systemd 仍崩溃 → 服务脱离 systemd + Windows 看门狗（最终方案）
- 用户反馈 127.0.0.1:3000 打不开，查实：systemd 在 13:03/13:04 又连续崩了两次（journald SIGTERM），服务重启初始化期间端口不可用
- wsl --update 到 2.7.11.0 未根治崩溃；wsl-pro 已禁用仍崩 → 判定 WSL 的 systemd 支持本身在这台机器上不稳定
- **最终方案（已实施）**：tacn 三服务脱离 systemd（disable --now），改用 nohup 独立进程 + 启动脚本 /root/tacn-start.sh（检查端口/进程不存在才拉起，幂等）；**Windows 侧看门狗** scripts\tacn-watchdog-win.ps1 每 2 分钟检查 localhost:8000/3000，挂了自动调 wsl 拉起 → 已注册计划任务 TacnWatchdog（2 分钟重复，999 天）
- 这样 systemd 崩不崩都不影响股票服务；WSL 整个重启后看门狗也会自动拉起
- 验证：看门狗手动触发 LastResult=0，frontend/backend 均 200；SYNC 任务 SyncWslPortProxy 保持开机运行

## 13:20 远程桌面弹窗排查 → WSLg 触发，已禁用
- 用户电脑弹“无法加载远程桌面服务 ActiveX 控件 rdclientax.dll”，怀疑木马
- 排查：无远控软件/无 4625 登录失败/3389 未监听/启动项干净/海王星无 RDP 引用 → 排除木马
- 真凶：WSL 目录 C:\Program Files\WSL\ 下有 rdclientax.dll（WSLg 自带），但精简系统 System32 里没有；WSLg 每次启动 WSL 时用远程桌面协议（msrdc.exe /wslg /silent ...wslg.rdp），加载失败就弹窗
- 实锤：3 个 msrdc.exe 进程启动时间 13:03:12/13:04:32/13:05:00 正是用户看到弹窗的时刻
- 修复：.wslconfig 加 guiApplications=false（股票系统是网页界面，不需要 WSLg），重启 WSL 后 WSL 内 wslg 进程=0，清理 msrdc 残留；服务由看门狗/start 脚本自动拉起，前后端 200
