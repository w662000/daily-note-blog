# 技术点 · 非对话型生成模型的接入范式：异步任务、结果接口与调用规范固化

> 对应项目轴 Handoff：`2026-08-01-handoff-为-workbuddy-接入-agnes-生图生视频能力并固化调用规范.md`
> 目的：从该项目提炼**可复用技术资产**——文生图/文生视频这类"非对话型"模型该怎么接、异步任务怎么取结果、调用规范怎么固化成可被任意模型复用的技能。下次接任何一家生成类 API，直接套这套流程与排错表。

## 一、技术选型

| 选型项 | 选定 | 落选 | 依据 |
|---|---|---|---|
| 调用脚本依赖 | **Python 标准库 `urllib`** | requests / SDK | 技能要在任意环境一键跑，装包会引入失败面；stdlib 足够覆盖 POST/GET/轮询/下载（T1） |
| 视频结果获取方式 | **API Key 调结果接口 `/agnesapi`** | 登录控制台取 cookie | 官方文档明确推荐方式只需 API Key，响应顶层 `url` 即直链。曾误判"必须 cookie"，纯属没读文档（T0 官方文档纠偏） |
| 生成任务模型 | **异步：创建 → 轮询状态 → 取结果** | 同步等待返回 | 视频生成实测 72 秒 ~ 4 分钟不等，同步必超时（T1） |
| 重试策略 | **429/5xx 温和退避重试，其余不重试** | 全错误码重试 | 参数类错误重试无意义还烧配额；503 属服务瞬时不可用，退避后大概率成功（T1，生图一次 503 重试即成） |
| 规范文档存放 | **单一真源 + 会话副本，真源放不参与自动搬运的目录** | 多处各留一份 | 多副本必漂移；真源要放在不匹配自动化命名模式的目录，避免被流程二次移动（T1） |
| 沉淀形态 | **用户级技能（SKILL.md + 脚本）** | 只写文档 | 文档要人去找，技能可被触发词直接加载，坑位随调用自动生效（T1） |

## 二、实施要点与关键技术

1. **对话端点返 404 ≠ 模型下线。** 生成类模型不接 `/chat/completions`，走各自专用端点。删条目前必须先打平台 `/v1/models` 只读清单核对。这个坑同期栽过两次（一次是模型 id 带了多余前缀，一次就是本次生成类模型被误删）（T1）。

2. **生图：参数位置有讲究。**
   ```
   POST https://api.agnes-ai.cn/v1/images/generations
   ```
   - `response_format` **必须放进 `extra_body`**，放顶层会被忽略（甚至 400）。
   - 图生图把源图放 `extra_body.image`。

3. **生视频：端点、帧数、异步三个坑。**
   ```
   POST https://api.agnes-ai.cn/v1/videos          # 注意不是 /videos/generations
   ```
   - `num_frames` 必须满足 **`8n+1` 且 ≤ 441**，不满足直接报错。
   - 返回 `task_id`，轮询 `GET https://api.agnes-ai.cn/v1/videos/{task_id}`（单 `/v1`）直到状态 `completed`。

4. **状态接口 ≠ 结果接口（本项目最大纠偏）。** 轮询接口只告诉你"做完了没"，**不给成片直链**。取片要另调结果接口：
   ```
   GET https://api.agnes-ai.cn/agnesapi?video_id=<VIDEO_ID>&model_name=agnes-video-v2.0
   ```
   响应顶层 `url` 字段即 mp4 直链，`curl` 直接下。此前只轮询状态接口就断定"没有直链、必须登录控制台拿 cookie"，是完全错误的结论，白折腾了一轮（T0 官方文档为准）。

5. **Windows 下载证书吊销检查失败**：走本地代理时 `curl` 报 `CRYPT_E_REVOCATION_OFFLINE`（schannel 无法在线校验吊销列表）。解法：`curl --ssl-no-revoke`（T1）。

6. **不要用"一般规律"预设模型能力。** 曾基于"文生视频通常无配音"告诉用户成片静音，实测这个模型会生成简单音效（怒吼类）。凡涉及模型输出特性，一律以实跑为准（T1）。

7. **生成耗时高度不稳定，批量任务要留时间预算。** 同为 121 帧，一次 72 秒、一次 2 分 11 秒（主要卡在排队段）；185 帧约 4 分钟（T1）。

8. **内容策略会静默弱化画面**：涉及血腥类描述（如肢体伤害）时输出会被淡化，需改写 prompt（T1）。

9. **技能正文要精简。** SKILL.md 是运行时加载物，调试过程记录应放记忆文件而不是塞进技能正文——同期把一个 222 行的技能压到 27 行（T1）。技能里只留：完整流程 + 所有易踩坑 + 触发词。

10. **文件名里的斜杠**：Windows 禁止文件名含 `/`，规范文档标题需要"生图/生视频"时用全角 `／` 规避（T1）。

## 三、模块职责划分

- **规范文档（唯一真源）**：承载连接信息、完整调用流程、给模型看的系统提示（指针版 + 内联版）、排错表。它的读者既是人也是模型。
- **一键脚本**：把流程固化为可执行路径，内置退避重试；不做业务判断，只保证"给参数就能出片"。
- **技能（SKILL.md）**：触发层 + 坑位清单。让"用 X 生图/生视频"这句话就能加载全部上下文，无需重新推导。
- **模型清单条目**：只声明"这个模型存在、属生成类、能力字段如何"，不承载调用细节。
- **排错表**：把已知失败模式（接口不符 / 503 / SSL 吊销 / 帧数非法 / 参数位置错）与对应动作一一对应，是"下次别再查一遍"的核心资产。

## 四、如何选型（可复用的决策方法论）

- **接入陌生 API 的第一步永远是读官方文档，不是猜路径。** 本项目最大的一次返工（cookie 误判）根因就是只调了状态接口没调结果接口，而文档里写得清清楚楚。
- **判断一个模型"是不是没了"的正确顺序**：① 打平台只读模型清单 → ② 若在清单里，找它的专用端点 → ③ 都不通再判定下线。跳过前两步就会误删。
- **同步还是异步**：看单次任务耗时的**上限**（不是均值）。上限超过网关超时就必须走异步 + 轮询。
- **重试哪些错误码**：只重试"瞬时"类（429 限流、5xx 服务端）；参数类（4xx）和资源不存在类（404）重试纯属浪费。
- **规范该沉淀成文档还是技能**：一次性的写文档；会反复调用、且坑位多到记不住的，必须沉淀成技能——判断标准是"下次做这件事需不需要重新推导"。
- **真源唯一化**：任何"会被多处引用的规范"都要指定唯一真源并删掉其他副本，且真源存放位置要避开自动化流程的命名匹配范围。

## 六、技术结合点

- **只读模型清单 + 专用端点探测**：清单证明"模型还在"，端点探测证明"这样调能通"。两者结合才把"chat 404"从"删除依据"降级为"信息不足"，直接避免误删。
- **异步轮询 + 结果接口**：轮询解决"什么时候好"，结果接口解决"成品在哪"。只做轮询会得出"没有直链"的错误结论——这正是本项目最贵的一课。
- **stdlib 脚本 + 技能触发词**：脚本保证零环境依赖，技能保证零记忆依赖。合起来才实现"任何模型、任何会话，说一句话就能生成"。
- **排错表 + 退避重试**：退避重试处理瞬时故障，排错表处理确定性故障。没有排错表，重试会把参数错误也无脑重试；没有重试，一次 503 就中断整条链路。
- **规范文档双版本（指针版 + 内联版）**：指针版给上下文充裕的场景（指路即可），内联版给上下文紧张或无法读文件的场景（把关键参数直接写进提示）。同一份知识两种投递方式，覆盖面显著变宽。
