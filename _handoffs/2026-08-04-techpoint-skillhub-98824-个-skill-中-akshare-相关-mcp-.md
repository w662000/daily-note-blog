# 技术点 · 大型技能库内特定技术（akshare）相关条目的精确检索与验证落地

> 对应项目轴 Handoff：`2026-08-04-handoff-skillhub-98824-个-skill-中-akshare-相关-mcp-.md`
> 目的：从该项目提炼**可复用技术资产**——怎么在 10 万级技能库里精确检索某个库/技术（如 akshare）相关的技能、怎么区分"精确命中"与"宽口径同类"、检索出来后怎么真正接进工作流（MCP 接入 + 安全扫描）。这是前几篇"采集—筛选—建站"链条的"定点取用"环节，做"从技能库找可用工具并落地"时直接复用。

| 选型项 | 选定 | 落选 | 依据 |

## 二、实施要点与关键技术

1. **多字段模糊匹配的写法**：对 `name / slug / description / description_zh / tags / labels / category / source / upstream_url / homepage` 拼成一段文本，做大小写不敏感匹配，文本含 `akshare` 即计入。漏掉任一字段都会低估命中数（T1）。

2. **精确 vs 宽口径的产出区分**（T1，本项目实测）：
   - **精确命中 akshare：102 个**（全部集中在 `data-analysis` 与 `professional` 两类），是真正的"akshare 相关 MCP skill"核心清单。
   - **金融类宽口径（股票/基金/期货/行情/量化/选股/财报/宏观/外汇/加密货币）：14,447 个**，其中仅命中宽口径的 3,656 个。
   - → 精确清单给"我要 akshare 封装"，宽口径给"我要中文金融数据能力"——口径要分清再对外。

3. **TOP 清单的读法**（T1，本项目结论）：
   - 人气最高：`A股量化 AkShare`（`akshare-stock`，⭐235 / 13,337 装），是最值得直接装的 akshare 封装。
   - 其余多为 `akshare-stock-*` / `akshare-*` 系列（数据获取、回测、复盘类）。
   - 宽口径头部集中在：选股/量化 4,249、交易/投资 4,170、金融/证券(宽) 7,794、个股分析/财报 3,189、A股/行情 1,882。

4. **真正落地选 MCP 而非 skill**：精确清单里 102 个大多是对 akshare 的薄封装，价值有限。实测优先接入 `akshare-one-mcp`（218★，隔离 venv 安装后写进 `~/.workbuddy/mcp.json`），温和单次验证：**初始化 OK、9 个工具全枚举、真实拉到 600519 茅台日线 OHLCV**（T1）。

5. **MCP 装包的两个坑**（T1）：
   - 托管 pip 默认 safe-delete 进回收站，沙箱没回收站 → `SAFE_DELETE_FAIL_CLOSED` 中止。**解法是给 pip 单独开沙箱豁免。**
   - 装第三方 skill 时 MSYS `tar` 解析 `C:` 失败、包装脚本 `/c/...` 被当成 `D:\c\...` 两个坑，用 `cygpath -w` 重写修复（Windows 路径转换陷阱）。

6. **第三方 skill 必须安全扫描再使用**（T1，关键经验）：
   - 实测 `china-stock-data` skill 的 `china_stock.py` 第 511 行把 Tushare 请求**静默重定向到非官方 `tushare.xyz`**；第 512 行**硬编码明文 Tushare token**（探测两端均失效）。
   - 修复：删重定向、删硬编码 token 改读 `TUSHARE_TOKEN` 环境变量，未设 token 时优雅降级。并把"如何获取 token"写进 SKILL.md。**此类"重写安装产物"动作属覆盖类，需用户明确授权后执行。**

7. **顺手修依赖 bug**：该 skill 的 `report` 命令调的 `ak.stock_jsyjs_anal_em` 在 akshare 1.18 已被移除，改成 `ak.stock_research_report_em` 并同步列名，实测能返回真实研报含 PDF 直链（T1）。

8. **B 路线（从 skillhub 直接装金融 MCP）四路全死**：详情页需登录（401）、目标 MCP 已下架（404）、GitHub 仓库 404、本地库只有元数据无正文。→ 这类"看起来能装"的条目要实测到点不为止，不能只看列表（T1）。

## 三、模块职责划分

- **检索器**：只负责在静态 JSON 上做多字段匹配 + 口径分流，产出精确清单与宽口径统计。
- **排序/报告**：只负责按 stars 组织 TOP N 与官方说明展开，给人做选型参考。
- **落地层（MCP 接入）**：只负责把"可用且高效"的接口接进工作流（venv + mcp.json），不维护一堆薄封装。
- **安全扫描器**：横切于落地层，对任何第三方 skill 做源码级检查（硬编码密钥、非官方域名、敏感重定向）。
- **合规约束**：贯穿检索与展示，禁止转售/搬运他人 skill 文件。

## 四、如何选型（可复用的决策方法论）

- **"找 X 相关技能"一定要分精确/宽口径两档**。精确口径回答"X 本身"，宽口径回答"和 X 同领域的更大能力池"。对外给清单前先声明口径，否则会被误读成"akshare 相关有 1.4 万个"。
- **10 万库里检索，多字段模糊匹配是底线**。关键词会藏在任何字段，只搜 name/description 必然低估。
- **落地优先"接一个全功能 MCP"而非"装一堆薄 skill"**。薄封装维护成本高、易过时；一个官方/高星 MCP 覆盖 9 工具更省心。
- **第三方 skill "信任"必须建立在扫描之后**。硬编码密钥、非官方域名重定向这类问题不会写在简介里，只有读源码能发现；且修复安装产物必须经授权。
- **列表里"可装"不等于"真能装"**。登录墙、下架、仓库 404、只有元数据无正文——这些要把实测进行到点位才确认。
- **沙箱装包先处理环境限制**：托管 pip 的回收站假设、Windows 的 `C:`/MSYS 路径转换，都是装包前就要处理的，否则中途 abort 浪费整轮。

## 六、技术结合点

- **精确检索 + 宽口径分流**：精确清单保证"找 akshare 不跑偏"，宽口径保证"想做金融数据分析还有更大池子"。两档一起交付，检索才有决策价值。
- **检索结果 + MCP 落地**：检索给出候选，落地只选最高效的那个（9 工具 MCP），避免"找到 102 个就装 102 个"的维护灾难。检索是输入，落地是收敛。
- **安全扫描 + 授权修复**：扫描发现问题（硬编码 token、非官方重定向），授权后改写安装产物，未设 token 时优雅降级——既用了第三方能力，又不把密钥和流量交给不可信方。
- **多字段匹配 + stars 排序**：匹配保证"不漏"，排序保证"先看到最好的"，两者结合让一份 10 万条清单变成可直接决策的 TOP 20。
- **实测到点 + 口径声明**：B 路线四路全死、宽口径 1.4 万这类结论，都建立在"实测到端点/仓库/登录态"之上，而不是列表快照。检索结论的可信度，最终取决于"验到哪一步"。
