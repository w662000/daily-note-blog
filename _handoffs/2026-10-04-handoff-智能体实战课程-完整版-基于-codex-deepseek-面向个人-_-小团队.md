## 学前必读：这套课到底在教你什么

很多人把「大模型」和「智能体（Agent）」混为一谈，结果花了几千块买课，最后只会跟 ChatGPT 聊天。这套课的第一性原理是：**大模型只是大脑，智能体是「大脑 + 手脚 + 记忆 + 计划」的完整人**。

- 大脑 = DeepSeek 这类推理模型，负责想。
- 手脚 = 工具调用（读文件、搜网页、跑代码、发消息），负责做。
- 记忆 = 短期上下文 + 长期知识库，负责不健忘。
- 计划 = 把大任务拆成步骤并依次执行，负责不跑偏。

Codex 在这里扮演「调度母体」：它是一个能挂载模型、管理工具、编排多步任务的运行环境（你可以把它理解成「智能体的操作系统」）。DeepSeek 是被塞进这个母体里的「脑子」。两者分工，后面每章都会落地。

> 一句话：你学完这套，能自己攒出一个「会自己干活」的 AI 员工，而不是只会聊天的玩具。

# 第一章：智能体底层认知与整体架构

## 1.1 本章目标
- 说清「大模型 ≠ 智能体」的本质区别。
- 理解智能体的四要素：模型、记忆、工具、规划。
- 搞懂 Codex 与 DeepSeek 在你这套系统里的角色分工。
- 判断「什么场景该自研 Agent，什么场景直接用现成平台」。

## 1.2 什么是 Agent 智能体（大白话）
普通大模型对话：你问一句，它答一句，答完就忘，也不会真的去帮你发邮件、改文件。
智能体：你给它一个目标（「把这篇网页整理成周报发到飞书」），它会自己**规划步骤 → 调用工具 → 看结果 → 调整 → 交付**。关键差异在四个字：**自主闭环**。

四要素拆解：
1. **模型（Model）**：负责推理和生成。这里是 DeepSeek。它决定「下一步该干嘛」。
2. **记忆（Memory）**：分两层。短期 = 当前对话的上下文窗口；长期 = 向量知识库（你公司的资料、历史对话）。没有记忆的 Agent 每次都像失忆。
3. **工具（Tools）**：Agent 的「手」。常见工具：文件读写、网络搜索、代码执行、数据库查询、发消息。模型本身不能碰文件系统，必须靠工具。
4. **规划（Planning）**：把「写一份竞品分析报告」这种模糊目标，拆成「搜 3 个竞品 → 各提取卖点 → 对比表格 → 生成结论」的可执行序列。

## 1.3 Codex 与 DeepSeek 的分工
- **Codex（调度母体）**：提供运行环境。它做的事——接收你的指令、把工具列表交给模型、解析模型「我要调工具 X」的意图、真正去执行工具、把工具返回结果再喂回模型、循环直到任务完成。它不负责「想」，负责「跑」和「管」。
- **DeepSeek（核心推理模型）**：负责「想」。每一次循环，Codex 把当前状态 + 可用工具描述发给 DeepSeek，DeepSeek 返回「下一步动作」（继续对话 / 调用某工具 / 输出最终结果）。

> 类比：Codex 是车间主任（排产、派活、验收），DeepSeek 是工程师（动脑设计方案）。

## 1.4 个人 / 小团队的边界判断
**适合自研 Agent 的场景**：
- 你的业务流程独特，现成 SaaS 套不上（如「把每天 50 条客户微信整理进自有 CRM」）。
- 数据敏感，不能出公网（本地数字人、本地知识库）。
- 需要长期跑、可复用、能积累资产的自动化。

**直接用现成平台更划算的场景**：
- 一次性、低频需求（偶尔翻译个文档）。
- 平台已高度垂直化（如剪映的 AI 成片、飞书的多维表格自动化）。
- 你没精力维护 API、调试报错。

判断口诀：**高频 + 独特 + 要沉淀 = 自研；低频 + 通用 + 不想维护 = 用平台。**

## 1.5 成本预估（以官网实时为准，以下为 2026 年量级参考）
- **模型调用**：DeepSeek 文本推理约 ¥1/百万输入 token、¥2/百万输出 token 量级（低价模型，远低于 GPT-4 级）。一个中等 Agent 任务约消耗 5k–30k token，单次成本几分钱。
- **硬件**：纯云端方案零硬件；本地数字人需一台有独显的机器（建议 8G 显存起步，如 RTX 3060 级），二手约 ¥1500–3000。
- **网络**：普通宽带即可，无需专线。
- **部署**：本地单机零服务器费；轻量云（如 2 核 4G）约 ¥50–100/月，够跑网页版数字人工具。
- **混合方案（推荐）**：推理走 DeepSeek 云端（便宜），敏感数据走本地（安全），月成本控制在 ¥100 内可跑通整套。

## 1.6 课程路线图
基础搭建（1–4 章）→ 内容生产（6–9 章）→ 业务软件（10–13 章）→ 工程交付（14–18 章）→ 优化与复盘（19–20 章）。中间穿插工作流（5）、办公集成（15）、知识库（16）、质量评估（17）。

# 第二章：环境准备、API 密钥与基础连通调试

## 2.1 本章目标
拿到能跑通的第一个对话：DeepSeek 接进 Codex，发一句能回一句。

## 2.2 DeepSeek API 申请与密钥管理
1. 注册 DeepSeek 开放平台账号（官网，以当前入口为准）。
2. 进入「API Keys」创建密钥，形如 `sk-xxxx`，**只显示一次，立刻复制保存**。
3. 密钥管理铁律：
   - 绝不写进代码里提交到 git。放环境变量或独立 `.env` 文件（加入 `.gitignore`）。
   - 不同项目用不同密钥，方便额度隔离和泄露溯源。
   - 发现泄露立即在后台「删除 / 重置」该密钥。

## 2.3 Codex 安装与本地部署
- **网页版**：最简单，浏览器打开即用，适合先跑通流程。
- **本地版**：下载安装包，注意环境依赖（Node/Python 版本）。装完检查端口是否被占用（默认常驻端口，具体看版本文档），跨域（CORS）报错多半是本地服务没配允许来源。

> 排错优先级：先 `ping`/看日志 → 再查端口占用（`netstat -ano | findstr 端口`）→ 最后查防火墙。

## 2.4 把 DeepSeek 接入 Codex（连通测试）
在 Codex 的模型配置里填入：
- Base URL：`https://api.deepseek.com/v1`（以官方文档为准）
- API Key：上一步的 `sk-xxxx`
- Model：`deepseek-chat`（通用）或 `deepseek-reasoner`（带推理链，适合复杂任务）

连通测试脚本（Python，验证密钥可用）：
```python
import os, requests
url = "https://api.deepseek.com/v1/chat/completions"
headers = {"Authorization": f"Bearer {os.environ['DEEPSEEK_KEY']}",
           "Content-Type": "application/json"}
data = {"model": "deepseek-chat",
        "messages": [{"role": "user", "content": "说一句你好"}],
        "stream": False}
r = requests.post(url, json=data, headers=headers)
print(r.status_code, r.json()["choices"][0]["message"]["content"])
```
返回 200 + 文本即连通成功。

## 2.5 基础参数调优
- `temperature`（0–1）：越低越稳（写代码/格式化用 0.1–0.3），越高越发散（脑暴用 0.7–0.9）。
- `max_tokens`：单次输出上限，长文生成设大些（如 2000–4000）。
- 上下文窗口：DeepSeek 约 32k–64k token 量级，超长任务要做「记忆压缩」或分段。
- `stream: true`：流式输出，体验更顺，前端要能处理分片。

## 2.6 安全规范
- 密钥防泄露：环境变量 + 不进 git + 定期轮转。
- 访问白名单：若自建服务，限制来源 IP。
- 日志脱敏：记录对话日志时，正则过滤掉 `sk-`、`密码`、`手机号` 等敏感串。
- 额度监控：设每日花费告警，防脚本死循环烧钱。

# 第三章：智能体核心提示词工程、角色与系统设定

## 3.1 本章目标
学会写「系统提示词（System Prompt）」，让 Agent 角色稳定、输出可控、失败有兜底。

## 3.2 System Prompt 的底层结构
一个能打的 System Prompt 必须拆清 5 块：
1. **角色（Role）**：「你是一个资深电商运营助手」。
2. **目标（Goal）**：「帮用户把商品卖点整理成详情页文案」。
3. **约束（Constraints）**：「只用中文、不编造参数、超出能力要说不会」。
4. **输出格式（Format）**：「严格输出 JSON，字段见下」。
5. **失败兜底（Fallback）**：「资料不足时返回 {"status":"need_more","question":"..."}」。

模板骨架：
```
你是一个{角色}。
目标：{目标}。
约束：
- {约束1}
- {约束2}
输出格式：{格式要求}
若无法完成：{兜底动作}
```

## 3.3 任务拆解 Prompt（CCoT 链式思考）
让 Agent 先列步骤再执行，避免一上来瞎干：
```
接到任务后，先输出：
## 任务拆解
1. ...
2. ...
确认无误后逐步执行，每步结束汇报进度。
```
这就是 CCoT（Chain of Thought 的协作版）——逼模型先想清楚路径。

## 3.4 记忆系统搭建
- **短期**：对话上下文直接携带。长任务用「每轮小结」压缩历史，防超窗口。
- **长期**：向量知识库（第 16 章详讲）。把公司资料切片向量化，检索相关片段塞进 prompt，让 Agent 「记得」你的私有信息。

## 3.5 输出强制格式化
要求「只输出可被程序解析的结果」：
```
只输出 JSON，不要任何解释文字。结构：
{"title": "...", "points": ["...","..."], "risk": "..."}
```
前端拿到直接 `JSON.parse`，省去正则抠文本。

## 3.6 提示词版本管理
- 每个任务的 prompt 存成独立文件（`prompts/详情页_v1.md`）。
- 做 A/B：同一任务跑 v1 和 v2，对比输出质量，留下胜者。
- 用表格记变更：「v2 改了约束第 2 条， hallucination 降 40%」。

# 第四章：给智能体挂载工具，实现工具调用能力

## 4.1 本章目标
让 Agent 不止会聊，还能「动手」：读文件、搜网页、跑代码。

## 4.2 工具调用原理
模型本身碰不了外部世界。工具调用流程：
1. 你给模型一份「工具说明书」（每个工具的名字、干嘛的、要什么参数）。
2. 模型判断「这步需要搜网页」，返回 `{tool:"web_search", args:{q:"..."}}`。
3. Codex 真的去执行这个工具，拿到结果（网页文本）。
4. 把结果塞回模型上下文，模型基于新信息继续。
这就是「感知—思考—行动」循环（ReAct 范式）。

## 4.3 基础工具接入
- **文件读写**：让 Agent 读本地文档、写输出。权限要收口（只给特定目录）。
- **网页搜索**：接搜索 API 或内置工具，返回正文。
- **代码执行**：给一个沙箱（Docker/隔离环境），Agent 写 Python 跑完返回 stdout。危险，务必隔离。
- **命令行**：同上，权限最大，只在可信环境开。

## 4.4 自定义工具开发
封装你自己的 API 成工具，注册到 Codex 工具列表。最小示例（伪结构）：
```
{
  "name": "查库存",
  "description": "根据商品ID查当前库存",
  "parameters": {"sku": "string"}
}
```
后端实现：收到 `sku` → 查数据库 → 返回 JSON。Agent 就能在对话里自然调它。

## 4.5 工具调用失败处理
- **重试**：网络抖动自动重试 2–3 次，指数退避。
- **异常捕获**：工具抛错时，把错误信息回给模型，让它换思路而不是卡死。
- **人工介入分支**：连续失败 N 次 → 暂停并推送「需要人处理」消息，别无限循环烧钱。

## 4.6 实战：信息搜集 Agent
目标：给一个主题，自动搜 5 篇资料 → 各写 100 字摘要 → 汇总成一份简报。
工具：web_search + 文件写入。System Prompt 约束「只引用搜到的内容，不编造」。跑通后你就拥有了一个 24 小时不累的研究助理。

# 第五章：智能体工作流编排，多子 Agent 协同框架

## 5.1 本章目标
单 Agent 容易顾此失彼。学会把任务分给「提案 Agent + 评审 Agent + 执行 Agent」。

## 5.2 为什么要多 Agent
单 Agent 同时想「写方案」和「检查方案对不对」会左右互搏。拆开后：
- 提案 Agent：只管产出。
- 评审 Agent：只管挑刺、打分。
- 执行 Agent：只管落地。
质量靠「生成—评审—修订」闭环保证。

## 5.3 工作流定义
- **顺序**：A 做完 B 才做（如先搜后写）。
- **并行分支**：多个子任务独立跑（如同时搜 3 个竞品）。
- **条件跳转**：评审不通过 → 回到提案重做。
- **循环**：直到评审分 ≥ 阈值。

## 5.4 消息传递与上下文隔离
子 Agent 之间不共享全部上下文（防干扰），只传递「交接物」（如提案 Agent 把方案文本交给评审 Agent）。用任务 ID 串联，结果可校验。

## 5.5 任务调度
- 优先级队列：急的任务先跑。
- 超时中断：单步超 5 分钟强制终止，防卡死。
- 断点续跑：任务状态落盘，崩溃后从最后成功步恢复。

## 5.6 实战：双人协同 Agent
搭一个「方案生成 + 评审校验」管线：提案 Agent 出方案 → 评审 Agent 按清单打分（完整性/可行性/合规）→ 低于 80 分打回重做 → 通过则交付。你会直观看到质量提升。

# 第六章：搭建详情页自动化流程（做图通用）

## 6.1 本章目标
输入一个商品，自动产出「文案 + 图片提示词 + 排版草稿」，可直接给设计师或绘图模型。

## 6.2 需求拆解
Agent 接收商品名/卖点，输出：
- 详情页结构（首屏卖点、参数表、场景图、信任背书……）。
- 每屏文案（大白话，突出痛点）。
- 每屏图片提示词（英文 prompt，喂给绘图模型）。

## 6.3 对接绘图模型
把图片提示词批量发给绘图 API（如即梦/可灵/Stable Diffusion），生成素材。注意尺寸统一（如 800×1200 竖图）。

## 6.4 自动排版
用 Markdown 或 HTML 模板把「图 + 文」拼成草稿，导出给设计师微调，或直接进剪辑/上架流程。

## 6.5 批量迭代
同一商品生成 3 个版本 → 人工/评审 Agent 选优 → 一键导出。

# 第九章：用智能体做故事板视频

## 9.1 本章目标
输出专业分镜表，直接交给剪辑师。

## 9.2 故事板结构化
每镜头含：镜号、画面描述、运镜、台词、时长、音乐/音效。

# 第十六章：知识库 RAG 接入，私有资料赋能智能体

## 16.1 本章目标
把公司 PDF/Word/飞书文档变成 Agent 的「长期记忆」。

## 16.2 RAG 原理
文档 → 切片（chunk）→ 向量化（embedding）→ 存向量库 → 用户提问时检索最相关片段 → 拼进 prompt → 模型基于片段作答。核心四步：切、嵌、召、答。

## 16.3 文档导入
批量导入私有文档，自动切片（建议 300–800 字/片，重叠 10% 防断义）。

## 16.4 挂载知识库
Agent 回答前先检索，只基于检索片段作答，并附出处。

## 16.5 幻觉抑制
要求「答案必须能在引用片段中找到，找不到就说不知道」，并标注来源段落，大幅降幻觉。

## 16.6 实战
搭一个私有业务知识库 Agent：导入产品手册 + 历史工单 → 客服问题自动基于资料答，引用原文。

# 第十七章：Agent 评估体系，自动校验输出质量

## 17.1 本章目标
不让 Agent 瞎产出，建立自动打分与双 Agent 互校。

## 17.2 打分规则
定义维度：完整性、准确性、格式合规、合规红线。每项 0–100，加权总分。

## 17.3 双 Agent 校验
生成 Agent 出稿 → 评审 Agent 按清单打分 → 不达标打回。互相独立，避免自欺。

## 17.4 自动发现错误
评审 Agent 专查：幻觉（无出处）、逻辑矛盾、格式崩坏。命中即标记。

## 17.5 质量监控
批量任务记录每单分数，低于阈值的自动重试；日志留存，持续迭代 prompt。

# 第十九章：成本、限流、并发与性能优化

## 19.1 本章目标
让 Agent 长期跑不破产、不卡死。

## 19.2 计费优化
- 长上下文任务用便宜模型（DeepSeek）而非旗舰。
- 精简 System Prompt，去掉冗余描述，省输入 token。
- 用 `max_tokens` 上限防失控输出。

## 19.3 缓存策略
相同查询（如「公司简介」）结果缓存，命中不调 API，省钱提速。

## 19.4 并发与限流
任务进队列，限制同时请求数；监控 429 限流，自动退避重试，防超额扣费。

## 19.5 混合推理
简单任务走本地小模型，复杂走云端，降 API 开销。

## 19.6 稳定性监控
心跳检测 + 花费告警 + 错误率告警，异常自动通知人。

# 第二十一章：工具 / 平台选型与成本速查（新增 · 实战必备）

> 本章为新增。把课程里散落的选型决策集中成一张表，落地前先翻这章。
> 价格/版本以各官网实时为准（中低可信），此处给 2026 年量级参考。

## 21.1 推理模型选型
| 模型 | 定位 | 价格量级(参考) | 适用 |
|---|---|---|---|
| DeepSeek-chat | 通用低价 | ¥1–2/百万 token | 日常 Agent 主力 |
| DeepSeek-reasoner | 带推理链 | 略高 | 复杂拆解/数学 |
| 本地小模型(如 Qwen) | 离线零成本 | 电费 | 敏感/高频简单任务 |

## 21.2 工具链选型
- 搜索：内置搜索工具 / SerpAPI（付费）/ 自建爬虫。
- 绘图：即梦、可灵、Stable Diffusion（本地免费但吃显卡）。
- 语音：TTS 云服务 / 本地 Bark-CN、GPT-SoVITS。
- 数字人：本地模型 / 云端 API（按分钟计费）。
- 部署：Docker（本地）、轻量云（分享）、Cloudflare（边缘）。

## 21.3 成本速算公式
月成本 ≈ 调用次数 × 单次 token × 单价 + 服务器费 + 绘图/语音按量费。
例：日 200 次任务，单次 1 万 token，DeepSeek 单价 ¥1.5/百万 → 月约 ¥9 + 云 ¥80 ≈ ¥90/月。

# 第二十四章：故障排查速查表（新增 · 排错手册）

> 本章为新增。把高频报错和对应解法列成表，遇事翻这章。

| 现象 | 可能原因 | 解法 |
|---|---|---|
| 401/403 | 密钥错/过期 | 重设密钥，检查环境变量是否注入 |
| 429 | 限流 | 降并发，加退避重试，查额度 |
| 输出非 JSON | 模型跑偏 | 强化格式约束 + 重试解析 |
| 工具调用死循环 | 无终止条件 | 设最大步数 + 人工介入 |
| 跨域 CORS | 本地服务未配来源 | 服务端加 `Access-Control-Allow-Origin` |
| 上下文超窗口 | 长任务未压缩 | 每轮小结压缩历史 |
| 数字人卡顿 | 显存不足 | 换小模型/降分辨率 |
| 知识库答非所问 | 切片太大/检索不准 | 调小 chunk，加重排 |
