### 7. GLM-4.1V 报错三轮排查（一次典型的"以为修好了其实没有"）

用户在客户端切到 GLM-4.1V 后报 `400 max_tokens 参数非法：限制数值范围[1,16384]`，前后查了三轮才真正解决：

- **第一轮**：加了 `maxOutputTokens: 16384`。用户重启后**还是报错**。
- **第二轮（字段名错了）**：重新查实，WorkBuddy 5.2.5 客户端实际读的是 `maxTokens`（驼峰单数），不是 `maxOutputTokens`。改完后 `[1,16384]` 那个错消失了——证明字段名这轮修对了。**自查教训**：上一轮我只读了"接口定义"类文档（官方 API 文档、模型 catalog），没读"踩坑实测"类文档（CSDN 实测文、报错修复贴），所以下错判断。以后查"某字段在客户端里是否生效"，优先信踩坑实测文。
- **第三轮（换了个错，是上下文溢出）**：新报错变成 `inputs tokens + max_new_tokens must be <= 65536. Given: 90196 inputs tokens`。这是完全不同的问题——4.1V 的**总上下文只有 65536**（不是"输入 65536 + 输出 16384"），而当时那个会话已经堆到 90196 tokens。**配置解决不了**，`maxInputTokens` 只是显示字段不是截断开关。唯一解法是开新会话，或换 128K 上下文的 `GLM-4.6V-Flash`（免费视觉档）。
- **21:10 用户确认修复成功**：新会话里 4.1V 4 秒响应、输出干净。

同时把 4.1V 的另一个坑摸清了：它输出重复啰嗦 + 残破 HTML 标签 + 答非所问，**不是配置问题，是模型本身的已知 bug**——THUDM 官方 README 公开承认 overthink / repeat / character escaping。官方在 4.5V 修掉了，而 4.5-Flash 已下线，所以真正的替代是 `GLM-4.6V-Flash`（免费、128K、不强制 CoT、支持工具调用）。

**另一个省钱提醒**：`glm-4.6v-flash`（9B）永久免费不扣额度，而 `glm-4.6v`（106B）是付费会扣资源包的——名字太像容易误切，已把后者改名为 `GLM-4.6V (付费)` 防误点。
