# 项目管理思维工具全景回顾

> 目的：把你学过的项目管理与思维工具列全，每个给出 20~40 句的深度解释（起源、核心思想、步骤要素、适用场景、作 agent 指导纲要的适配度），方便你回忆并挑选哪些适合作为 agent 的指导性纲要。
> 组织方式：按功能分类，共九大类、约 30 个工具。每个工具末尾标注【agent 适配度】高/中/低，并简述理由。

---

## 一、循环改进类（持续迭代）

### 1. PDCA 戴明环（Plan-Do-Check-Act）
PDCA 又称戴明环，由美国质量统计学家沃尔特·休哈特（Walter Shewhart）在 1920 年代提出雏形，后由其学生 W. 爱德华兹·戴明（W. Edwards Deming）在日本战后质量复兴运动中大力推广，因此得名。它的核心思想是：任何改进都不是一次完成，而是通过"计划—执行—检查—处理"四个阶段不断循环、螺旋上升。Plan 阶段要明确目标、拆解任务、识别变量、预测风险并制定可验证的标准。Do 阶段是小范围、受控地执行计划，尽量保持单一变量，避免一次性引入多个改动导致无法归因。Check 阶段用可证伪的证据对照 Plan 中设定的标准，看结果是否符合预期、偏差来自哪里。Act 阶段则把成功的做法标准化固化、把失败的教训沉淀，未解决的问题进入下一轮 PDCA。PDCA 的精髓在于"小步快跑、闭环验证、失败可控"——它不追求一次做对，而追求每轮都能从偏差中学习。它特别适合不确定环境下的工程改进，因为每轮 Check 都是一个"刹车点"，防止一头扎下去猛干。对 agent 而言，PDCA 的价值在于强制插入 Check 环节，避免"只 Do 不 Check"的盲跑。它和"温和测试、单一变量"的红线天然契合：Do 阶段单次低频，Check 阶段用落盘数据证伪。弱点是它本身不规定"怎么拆任务、谁来查机制"，需要配合调查员/挑刺员角色补全。
【agent 适配度：高】——已是 multi-agent-pdca skill 的骨架，Check 环节正好治"连跑不验证"。

### 2. DMAIC（Define-Measure-Analyze-Improve-Control）
DMAIC 是六西格玛（Six Sigma）的核心改进流程，由摩托罗拉工程师比尔·史密斯（Bill Smith）在 1980 年代提出，后经通用电气杰克·韦尔奇推广成为工业界标准。Define 是界定问题与客户痛点，明确"什么算改进完成"的量化标准。Measure 是建立基线数据，用真实测量而非直觉判断当前状态，避免凭印象归因。Analyze 是用统计工具（帕累托、假设检验、回归）找出影响输出的关键少数变量（vital few）。Improve 是针对关键变量设计并验证改进方案，同样强调小批量试点。Control 是把改进成果固化到流程/文档/自动化里，防止回退。DMAIC 比 PDCA 更"重"——它要求量化测量和统计分析，适合数据可得、可重复的制造/运营场景。它的最大贡献是"用数据说话、用统计找根因"，把"拍脑袋"赶出决策。对 agent 的启发是：改进前先 Measure 建基线，否则改进成功与否无法证明；这一点正好对应"落盘验证阈值"。在纯软件/脚本场景，DMAIC 的统计环节可能过重，但其"先量后改"的思想可简化为"先记 COUNT 再动手"。
【agent 适配度：中】——Measure/Control 思想可用，但完整六西格玛统计对 agent 过重；适合做数据治理类任务。

### 3. OODA 循环（Observe-Orient-Decide-Act）
OODA 由美国空军战斗机教官约翰·博伊德（John Boyd）提出，源于空战格斗理论，后扩展到商业和竞争战略。Observe 是快速感知环境变化（对手动作、自身状态、外部信号）。Orient 是 OODA 的核心——把观察到的信息放入自己的心智模型和文化背景中过滤、解读，形成判断；博伊德强调 Orient 决定了循环的快慢与质量。Decide 是基于判断选定一个行动方案。Act 是执行并立即回到 Observe，形成闭环。OODA 的精髓是"比对手更快地完成循环"——在动态对抗中，谁的 OODA 转得快、转得准，谁就掌握主动。它和 PDCA 的区别在于：PDCA 偏"内部改进闭环"，OODA 偏"外部对抗闭环"，强调速度和情境适应。对 agent 而言，OODA 适合"环境会变、对手会动"的场景，如反爬虫对抗、限流规避、A/B 测试调优。它的风险是过快循环可能牺牲深度，需要配 Check 节制。Orient 环节特别值得 agent 借鉴：同样的事实，不同的心智模型会得出不同判断——这正是"先搜再判"的价值，用查到的机制更新 Orient，避免凭旧假设误判。
【agent 适配度：中】——对抗/动态场景（限流、反爬）适用；需配 Check 防止过快盲动。

### 4. A3 报告 / A3 问题解决
A3 源于丰田生产系统，因把问题解决全过程写在一张 A3 纸上得名。它不是单一工具，而是一套"结构化讲故事"的方法：背景→现状→目标→根因→对策→计划→跟进。背景说清为什么要做这件事、对谁重要。现状用事实和数据描述，不带判断。目标设定可量化的改进点。根因常用 5 Whys 或鱼骨图深挖。对策针对根因而非症状。计划列出谁、何时、做什么。跟进定期回顾。A3 的力量在于"一页纸强制结构化"——逼你把模糊问题说清楚，且任何人看一页就能跟上。它强调"去现场看"（genchi genbutsu），反对坐在办公室想当然。对 agent，A3 是极好的"任务交接/方案呈现"模板：把调查员结论、规划员方案、挑刺员意见浓缩成一页，用户一眼看懂全貌。它也治"吞细节只报结论"的毛病，因为 A3 要求现状和根因必须写全。
【agent 适配度：高】——作方案呈现与任务交接的结构化模板非常合适；强制写全现状/根因契合"不折叠"红线。

## 二、问题分析与根因类（找准病根）

### 5. 5 Whys 五问法
5 Whys 由丰田生产系统创始人大野耐一（Taiichi Ohno）推广，是丰田"科学方法"的基石。做法极简：面对一个问题，连续问"为什么"，每一问基于上一答深挖，通常 5 次左右能触及根因（非严格 5 次，多少看深度）。它的哲学是"问题不会停留在表面，根因往往藏在 5 层之下"。经典案例：机器停了→保险丝断了→超载→轴承润滑不足→油泵吸不上油→油泵轴磨损→没有滤网导致碎屑进入。根因是"缺滤网"，对策是"装滤网并制定保养规程"，而非"换保险丝"这种治标。5 Whys 的关键是"沿因果链直线下钻"，避免横向发散；且每一层都要有事实支撑，不能凭猜测。它常与鱼骨图互补：鱼骨横向穷尽可能原因，5 Whys 纵向深挖一条链。弱点是不同人问出来的链可能不同，有主观性；且对"多重根因交织"的复杂问题，单条链可能遗漏。对 agent，5 Whys 是最轻量的根因工具，适合"撞错后别急着归 cookie，先问 5 个为什么"。
【agent 适配度：高】——撞错归因必备，专治"想当然猜 cookie"。

### 6. 鱼骨图 / 石川图（Fishbone / Ishikawa Diagram）
鱼骨图由日本质量管理大师石川馨（Kaoru Ishikawa）在 1960 年代提出，因形似鱼骨得名，又称因果图。把问题（鱼头）放在右边，左边鱼骨是原因大类，每根大骨下再细分小骨。制造业常用 6M 分类：人（Man）、机（Machine）、料（Material）、法（Method）、测（Measurement）、环（Environment）。服务业常用 4P：政策（Policy）、流程（Procedure）、人员（People）、设施/技术（Plant/Technology）。它的核心价值是"穷尽式发散"——强迫团队把所有可能原因都摆出来，避免只盯着一个疑似原因（如只盯 cookie）。它和 5 Whys 是互补关系：鱼骨负责广度（有哪些可能），5 Whys 负责深度（这条链到底为什么）。用法是先头脑风暴填满鱼骨，再用 5 Whys 或数据验证哪根骨是真因。弱点是容易变成"列清单但不验证"，需要配合数据/实验确认。对 agent，鱼骨图适合"故障复盘时把所有假设摊开"——比如抓取 0 条，把 cookie/限流/网络/代码/数据格式/权限全列出来再逐一排除，而不是一开始就锁死 cookie。
【agent 适配度：高】——故障排查时把假设摊开逐一证伪，治"先入为主"。

### 7. MECE（相互独立、完全穷尽）
MECE 是麦肯锡咨询顾问芭芭拉·明托（Barbara Minto）在《金字塔原理》中系统化的原则，全称 Mutually Exclusive, Collectively Exhaustive。相互独立指分类之间不重叠，完全穷尽指分类合起来覆盖全部情况。它是"想清楚、说清楚"的底层纪律：任何拆分（问题分解、方案罗列、原因分类）都应满足 MECE，否则要么有遗漏要么有重复。MECE 不直接给答案，但保证了思考的完整性与不重复，是结构化思维的地基。它常与金字塔原理配合：结论先行，论点 MECE 分组支撑。判断一个分类是否 MECE 的方法是问"有没有既属于 A 又属于 B 的"（查独立）和"有没有既不属于 A 也不属于 B 的"（查穷尽）。对 agent，MECE 是"拆任务、列方案、排故障"时的自检规则——比如"爬取失败的原因"要 MECE：cookie 失效 / 限流 / 网络 / 代码 bug / 数据源变更 / 权限，六类不重叠且覆盖。它治"漏想一个原因"和"两个 agent 干同一块"。
【agent 适配度：高】——任务拆分与原因分类的自检规则，保证分工不重叠不遗漏。

### 8. 第一性原理（First Principles Thinking）
第一性原理可追溯到亚里士多德，近年因埃隆·马斯克（Elon Musk）在航天、电池、隧道领域的运用而广为人知。它的核心是"把事物拆解到最基本、不可再分的事实，再从这些事实向上重新推理"，而不是用类比（"别人怎么做我就怎么做"）来思考。类比思维快但容易陷入路径依赖；第一性原理慢但能突破常规。马斯克的例子：电池贵不是因为"电池就该贵"，而是拆到镍/钴/铝/碳/聚合物原料成本，发现原料本身只要 80 美元/千瓦时，于是自建工厂把电池成本打下来。第一性原理的关键是区分"事实"与"假设/惯例"——很多"必须如此"其实是可挑战的假设。对 agent，第一性原理适合"别人都这么做但我想知道为什么"的场景，以及"方案卡住时回到底层重新想"。它也防止"抄作业抄错"——比如别人用多线程爬虫，但回到第一性原理：微信限流是按账号/IP 累计频率，多线程只会更快撞限流，所以串行才是对的。
【agent 适配度：中】——适合方案选型与"破除惯例"时刻，但日常执行用不上；作挑刺员视角很合适。

### 9. 奥卡姆剃刀（Occam's Razor）
奥卡姆剃刀由 14 世纪英国修士奥卡姆的威廉（William of Ockham）提出，原则是"如无必要，勿增实体"（Entia non sunt multiplicanda praeter necessitatem）。在问题解释上，它指"当多个假设都能解释同一现象时，选最简单的那个（假设最少的那个）"。它不是"简单的必然对"，而是"简单的更可能是对的，因为假设越少出错点越少"。它是一种概率启发性，不是逻辑证明。应用：抓取 0 条，假设 A 是"cookie 过期"，假设 B 是"cookie 过期+半成品+pass_ticket 缺失+data_ticket 轮换+频率限制"五合一——按奥卡姆，应先验证单一假设 A；若 A 不成立再换，而不是一开始就堆五个假设。它和第一性原理都强调"回到基本"，但方向相反：第一性原理从底层重建，奥卡姆从顶层选最简。对 agent，奥卡姆剃刀是"归因时的克制纪律"——别一上来就构造复杂多因假设，先用最简假设验证。
【agent 适配度：中】——归因时的克制原则，治"堆假设"；但有时真因确实复杂，需配数据验证。

## 三、目标与优先级类（先做对的事）

### 10. SMART 原则
SMART 由乔治·多兰（George T. Doran）在 1981 年的论文《There's a S.M.A.R.T. way to write management's objectives》中提出，后经彼得·德鲁克目标管理（MBO）思想演化普及。五个字母：Specific 具体（目标清晰不含糊）、Measurable 可衡量（有量化指标判断达成）、Achievable 可实现（在资源约束内可达）、Relevant 相关（与上级目标/业务价值挂钩）、Time-bound 有时限（明确截止时间）。SMART 的价值在于把"愿望"变成"目标"——愿望是"提高采集成功率"，SMART 目标是"在 8 月 2 日前，单次采集 6 个号成功率 100%、单号文章数≥50、不触发 200013"。它治三种常见病：目标模糊无法验收、目标过高无法达成、目标与业务无关白忙。它的弱点是偏保守——Achievable 约束可能抑制突破性目标，需配合 OKR 的野心目标平衡。对 agent，SMART 是"把用户模糊需求翻译成可执行任务"的标尺，尤其 Measurable 和 Time-bound 两条：每个任务都要有"多少条/多少秒/到哪天"的量化验收线。
【agent 适配度：高】——把模糊需求翻译成可验收任务的标准，Measurable/Time-bound 是 agent 任务必备。

### 11. MoSCoW（Must / Should / Could / Won't）
MoSCoW 是优先级排序方法，由戴·克莱格（Dai Clegg）在 Oracle 工作时提出，广泛用于敏捷项目范围管理。把需求/任务分四档：Must 必须做（不做项目失败）、Should 应该做（重要但可延期）、Could 可以做（锦上添花）、Won't 这次不做（明确排除）。大写字母拼成 MoSCoW 便于记忆。它的核心是"在资源有限时，先保 Must，再争取 Should，Could 看情况，Won't 要敢于砍"。它治"什么都想做结果什么都没做好"和"不敢说不导致范围蔓延"。关键动作是每个迭代/批次开始前重新分级，因为优先级会随环境变化。对 agent，MoSCoW 适合"任务清单太长、资源（时间/频率预算/agent 数）有限"时排序——比如限流冷却期只能跑一次，那 Must 是"跑通验证"、Should 是"灌 D1"、Could 是"加 KV 计数"、Won't 是"加并发加速"。
【agent 适配度：高】——任务排序与范围控制，适配资源受限（频率预算、单次执行）场景。

### 12. 艾森豪威尔矩阵（紧急/重要矩阵）
艾森豪威尔矩阵源自美国前总统艾森豪威尔的"重要 vs 紧急"区分，后由史蒂芬·柯维（Stephen Covey）在《高效能人士的七个习惯》中系统化为四象限工具。四个象限：重要且紧急（立刻做，如线上故障）、重要不紧急（计划做，如能力建设、风险预防——柯维认为这是高产出区）、紧急不重要（委托/批量做，如部分会议、即时消息）、不重要不紧急（不做，如无意义刷屏）。它的洞见是：大多数人被困在"紧急不重要"和"紧急且重要"里，而真正拉开差距的是把时间投到"重要不紧急"象限。它治"救火式忙碌"和"分不清轻重"。对 agent，这个矩阵可用于"任务来了先分类再执行"——比如自动化的每日抓取是"重要不紧急"应排期，而"撞 200013 了"是"重要且紧急"应立刻停手，而不是继续连跑。
【agent 适配度：中】——任务分级有用，但 agent 任务多为流水，象限划分场景有限。

### 13. OKR（目标与关键结果）
OKR 由安迪·格鲁夫（Andy Grove）在英特尔创立，后由约翰·杜尔（John Doerr）在《Measure What Matters》中推广，谷歌等公司广泛采用。结构是 Objective（目标，定性、有方向感、鼓舞人心）+ 3~5 个 Key Results（关键结果，定量、可衡量、有时限）。OKR 与 KPI 的关键区别：OKR 公开透明、与绩效脱钩、鼓励野心（理想达成率 70%，100% 反而说明目标太保守）。它强调"对齐"——上下级、跨团队 OKR 要相互支撑，避免各自为战。它也强调"聚焦"——一个周期通常只定 3~5 个 O，每个 O 配 3~5 个 KR，少即是多。弱点是若与绩效挂钩会扭曲成 KPI，失去鼓励冒险的本意。对 agent，OKR 思想可用于"项目级目标设定"——O 是"建立稳定的每日自动采集"，KR 是"连续 7 天单次成功率 100%""D1 每日新增≥50 条""零 200013 触发"。
【agent 适配度：中】——项目级目标对齐有用，但 agent 单任务粒度偏粗。

### 14. 80/20 法则（帕累托原则）
80/20 由意大利经济学家维尔弗雷多·帕累托（Vilfredo Pareto）发现——意大利 80% 土地由 20% 人拥有，后由约瑟夫·朱兰（Joseph Juran）命名为帕累托原则并引入质量管理。核心：在多数系统中，约 80% 的结果来自约 20% 的原因/投入。它的力量是"识别关键少数（vital few）与次要多数（trivial many）"，把有限资源砸在关键少数上。应用极广：80% 销售来自 20% 客户、80% bug 来自 20% 代码、80% 故障来自 20% 原因。它不是精确的 80/20，而是"分布不均"的隐喻。在质量改进中常配合帕累托图（按频次降序排列的柱状图）找最大贡献因素。对 agent，80/20 是"别平均用力"的提醒——比如 6 个公众号里可能 2 个贡献了 80% 文章量，优先保这 2 个；或 80% 的限流风险来自 20% 的请求模式（连跑），管住这 20% 就基本解决。
【agent 适配度：中】——资源分配与风险聚焦的指导原则，识别关键少数。

## 四、决策与多维思考类（想周全再定）

### 15. 六顶思考帽（Six Thinking Hats）
六顶思考帽由马耳他心理学家爱德华·德·波诺（Edward de Bono）在 1985 年提出，是一种"平行思维"工具。六顶帽子代表六种思维模式：白帽（客观事实与数据）、红帽（直觉情感与预感，不需理由）、黑帽（谨慎、风险、批判、找毛病）、黄帽（乐观、价值、利益、可行性）、绿帽（创造、替代方案、新点子）、蓝帽（控制流程、 meta、总结归纳）。传统讨论是"对抗式"的（你赞成我反对），六帽改为"平行式"——所有人同时戴同一顶帽，从同一角度看问题，再统一换帽，避免争吵内耗。典型顺序：蓝帽开场定流程→白帽摆事实→绿帽出方案→黄帽评价值→黑帽挑风险→红帽表达感受→蓝帽总结决策。它的价值是"把发散与收敛分离"，且强迫乐观（黄帽）和批判（黑帽）都被充分表达。对 agent，六顶思考帽是天然的多 agent 角色分配——挑刺员就是黑帽、规划员是绿帽+黄帽、调查员是白帽、用户/主 agent 是蓝帽。这正好印证了你 PDCA skill 里的角色设计。
【agent 适配度：高】——可直接映射为多 agent 角色分工，黑帽=挑刺员已是默认设计。

### 16. SWOT 分析
SWOT 由阿尔伯特·汉弗莱（Albert Humphrey）在 1960 年代斯坦福研究所提出（学界对其起源有争议，但常归于他），是战略分析经典工具。四象限：Strengths 优势（内部、正面）、Weaknesses 劣势（内部、负面）、Opportunities 机会（外部、正面）、Threats 威胁（外部、负面）。内部分析看自身资源/能力/短板，外部分析看市场/竞争/政策/技术趋势。SWOT 本身只摆事实，真正的价值在 TOWS 矩阵——把四象限交叉出策略：SO（用优势抓机会）、WO（补劣势抓机会）、ST（用优势避威胁）、WT（止损规避）。它的弱点是容易变成"罗列清单不行动"，需配合 TOWS 转策略。对 agent，SWOT 适合"方案选型"场景——比如选 Replit 还是 Cloudflare 部署：S（各自优势）、W（各自劣势）、O（各自机会）、T（各自威胁），再 TOWS 出推荐。它也适合"风险评估"——把外部威胁（限流、政策变化）单列一象限。
【agent 适配度：中】——方案选型与风险评估有用，但偏战略层，agent 单任务用不上。

### 17. 力场分析（Force Field Analysis）
力场分析由社会心理学家库尔特·勒温（Kurt Lewin）提出，基于其"场论"。核心：任何现状都处于"驱动力（推动改变）"与"阻力（阻碍改变）"的平衡中；要推动改变，要么增强驱动力，要么削弱阻力，后者通常更有效。做法是列出所有驱动力和阻力，按强度打分，分析哪条最关键，再设计对策。它的洞见是"别只想着加力，减阻往往更省事"——比如想让采集稳定，驱动力是"加并发加快"，阻力是"限流"；与其加驱动力（更猛爬），不如削阻力（降低频率、错峰），后者更可能成功。它和奥卡姆一样强调"识别真正的约束"。对 agent，力场分析适合"推动一个改变前先想清楚阻力"——比如想加自动每日采集，阻力有"cookie 失效""限流""机器关机"，逐条削阻比硬推更稳。
【agent 适配度：中】——变更前阻力分析有用，治"只想加力不想减阻"。

### 18. 决策矩阵 / 加权评分法
决策矩阵是把多个备选方案按多个评价维度打分、加权求和，选总分最高者的方法。步骤：列出备选方案→确定评价维度（如成本、速度、稳定性、可维护性）→给每个维度设权重→每个方案在每个维度打分→加权求和→选最高。它比纯直觉决策透明、可追溯，也便于团队讨论"为什么选 A 不选 B"。弱点是权重和打分仍带主观，需用数据校准。它常与 Pugh 矩阵（基准对照）结合。对 agent，决策矩阵是"方案选型时把维度摊开量化"的工具——比如选爬虫节奏方案，维度有"触发限流风险（权重高）""速度""实现复杂度""可维护性"，连跑方案在限流风险维度必拿低分，自然被淘汰。
【agent 适配度：中】——多方案多维度选型时量化对比，比拍脑袋强。

## 五、信息梳理类（把事说清楚）

### 19. 5W1H / 5W2H（六何法）
5W1H 起源于新闻学的"五个 W"（Who/What/When/Where/Why），加 How 构成六何法，中文常称"何人、何事、何时、何地、为何、如何"。5W2H 再加 How much（成本/程度）和 How many（数量）。它是"把一件事说全"的最小完整框架——任何任务/事件/需求都能用这六七个问题框住。Who 谁负责/谁受影响，What 做什么/产出什么，When 时间节点，Where 在哪/哪个系统，Why 为什么要做/业务价值，How 怎么做/方法步骤，How much 花多少成本/多少量。它的价值是"防止遗漏关键信息"——常见翻车就是只说了 What 和 How，漏了 When 和 Who，导致没人按时交付。对 agent，5W1H 是"接任务时的澄清清单"——用户说"采集更新"，agent 应确认 Who（哪个号）、What（文章还是阅读数）、When（每日几点）、Where（D1 还是本地）、Why（前端展示）、How（脚本路径）。它也是"任务交接文档"的标准结构。
【agent 适配度：高】——任务澄清与交接的标准框架，防信息遗漏。

### 20. STAR（情境-任务-行动-结果）
STAR 是行为面试的经典框架，用于结构化描述一段经历或一个案例。Situation 情境（背景/当时状况）、Task 任务（你要完成什么/目标）、Action 行动（你具体做了什么，重点）、Result 结果（产出与影响，能量化最好）。它的力量是"用具体案例证明能力"，而非空谈。它也治"流水账式汇报"——强迫把背景、目标、动作、结果讲清楚，缺一环就讲不圆。STAR 也常用于复盘和案例撰写：把一次成功/失败的项目按 STAR 整理，既清晰又可复用。对 agent，STAR 是"汇报与复盘"的结构模板——比如"采集翻车复盘"按 STAR：情境（每日采集任务）、任务（验证限流是否解除）、行动（连跑 4 次撞 200013）、结果（D1 零新增+触发封 1 天+学到 PDCA）。它让复盘有骨有肉，不折叠细节。
【agent 适配度：中】——复盘与汇报结构，适合事后总结；执行期用不上。

## 六、执行与流程类（把事做成）

### 21. 敏捷 / Scrum
敏捷由 2001 年《敏捷宣言》正式确立，Scrum 是其最流行的框架之一，源自 1986 年竹内弘高和野中郁次郎的《哈佛商业评论》论文，后由杰夫·萨瑟兰（Jeff Sutherland）和肯·施瓦伯（Ken Schwaber）在 1995 年系统化。核心是把大项目拆成短的迭代（Sprint，通常 1~4 周），每个 Sprint 产出可交付的增量，通过每日站会、Sprint 评审、回顾会持续调整。角色有产品负责人（Product Owner，管优先级）、Scrum Master（管流程）、开发团队（管执行）。工件有产品待办列表（Product Backlog）、Sprint 待办列表、增量。它的哲学是"拥抱变化、小步交付、快速反馈"，对抗瀑布式的大而全。对 agent，敏捷思想可用于"长任务拆 Sprint"——把一个复杂项目拆成多个可验证的小迭代，每个迭代有明确产出和回顾，而非一口气干到底。每日站会思想对应"进度同步"。
【agent 适配度：中】——长任务拆迭代思想有用，但完整 Scrum 仪式对 agent 过重。

### 22. 看板（Kanban）
看板源自丰田生产系统，由大野耐一在 1950 年代引入，后由大卫·安德森（David Anderson）在 2010 年系统化为知识工作方法。核心是"可视化工作流+限制在制品（WIP）+拉动式生产"。把任务卡片按列（待办/进行中/完成）贴在看板上，限制每列同时进行的任务数（WIP 上限），只有下游有空位时上游才能"拉动"新任务。它的力量是"暴露瓶颈、防止过载、平滑流动"——WIP 限制强迫专注，避免多任务并行导致的上下文切换损耗。它比 Scrum 更轻，没有固定迭代周期，强调持续流动。对 agent，看板思想可用于"多 agent 任务管理"——把任务列在看板上，限制同时进行的 agent 数（WIP），避免并发太多互相干扰或撞限流。TaskCreate/TaskList 工具本质上就是个轻量看板。
【agent 适配度：高】——WIP 限制思想正治"并发撞限流"；TaskList 即看板。

### 23. 关键路径法（CPM）/ PERT
CPM 由杜邦公司的摩根·沃克（Morgan Walker）和詹姆斯·凯利（James Kelley）在 1957 年开发，用于化工厂维护排程；PERT 由美国海军在 1958 年北极星导弹项目中开发。两者都用网络图表示任务依赖，找出"关键路径"——决定项目总工期的最长依赖链。关键路径上任何任务延期，整个项目就延期；非关键路径任务有浮动时间（slack）可弹性安排。CPM 用确定工期（适用于经验丰富的重复项目），PERT 用三点估算（乐观/最可能/悲观，适用于不确定性高的研发项目）。它们的价值是"识别瓶颈任务、优化资源分配"——把资源优先投到关键路径上才能缩短工期。对 agent，CPM 思想可用于"多 agent 任务排依赖"——找出哪些任务必须串行（关键路径，如先查机制才能规划）、哪些可并行（非关键路径），把 agent 优先派到关键路径任务上。
【agent 适配度：中】——多 agent 任务依赖排程有用，识别关键路径。

### 24. 甘特图（Gantt Chart）
甘特图由亨利·甘特（Henry Gantt）在 1910 年代推广（更早的版本可追溯到 1890 年代），是项目管理最经典的进度可视化工具。横轴是时间，纵轴是任务，每条横条表示一个任务的起止时间，可叠加依赖关系、里程碑、进度。它的价值是"一眼看清谁在何时做什么、任务之间如何重叠与衔接"，是排期和进度沟通的通用语言。弱点是静态、难反映动态变化，且任务过多时图会爆炸。现代工具（MS Project、Asana、Gridea 之类）把它做成交互式。对 agent，甘特图思想可用于"多 agent 任务时间排布"——把调查/规划/挑刺/执行各阶段按时间轴排开，明确哪个阶段并行、哪个串行。但 agent 任务多为短期，甘特图偏重，轻量任务用 TaskList 即可。
【agent 适配度：低】——偏重，agent 短期任务用不上；长周期多阶段项目才需要。

### 25. 精益（Lean）
精益源自丰田生产系统（TPS），由詹姆斯·沃马克（James Womack）和丹尼尔·琼斯（Daniel Jones）在《改变世界的机器》中提炼为"精益"理念。核心是"消除浪费、持续改善、尊重人"。七大浪费：过量生产、等待、运输、过度加工、库存、动作、缺陷返工。精益强调"价值流"——从客户视角定义价值，去掉所有不增值的步骤。工具包括 5S（整理/整顿/清扫/清洁/素养）、看板、节拍时间、单件流。它的哲学是"小批量、快流动、零库存"，对抗大批量带来的隐藏问题。对 agent，精益思想可用于"消除执行浪费"——比如连跑 4 次是"缺陷返工"浪费，应一次性做对；重复造轮子是"过度加工"，应复用已验证链路。"先搜再判"也是精益的"防错（poka-yoke）"思想。
【agent 适配度：中】——消除浪费与防错思想可用，指导执行效率与质量。

### 26. 约束理论（Theory of Constraints, TOC）
约束理论由以利亚胡·高德拉特（Eliyahu Goldratt）在 1984 年的小说《目标》（The Goal）中提出。核心：任何系统都至少有一个约束（瓶颈），系统产出由这个约束决定，优化非约束环节不会提升整体产出。聚焦五步法：1）识别约束→2）挖尽约束（充分利用）→3）服从约束（其他环节配合）→4）打破约束（增资源）→5）回到第 1 步（避免惯性）。它的洞见是"别平均优化，先找到瓶颈再针对它"。对 agent，TOC 思想可用于"识别任务链路的真正瓶颈"——比如采集链路 cookie→抓取→灌库，若瓶颈是"限流"，那优化 cookie 续期或灌库速度都没用，必须先解限流。这正好对应"先搜再判"——别盲目优化非瓶颈环节。
【agent 适配度：中】——识别瓶颈再针对优化，治"平均用力"。

## 七、责任与风险类（谁干、防什么）

### 27. RACI 责任分配矩阵
RACI 是责任分配矩阵，把每项任务与每个角色交叉，标注四种角色：R Responsible（执行者，真正干活的人）、A Accountable（最终负责人，只有一个，成败归他）、C Consulted（咨询者，被征求意见）、I Informed（知会者，被告知结果）。它的价值是"消除责任模糊"——常见翻车是"大家都以为别人负责"或"一个任务多个 A 互相推诿"。RACI 强制每项任务有且只有一个 A，避免责任真空。它也澄清谁要参与决策（C）、谁只需被告知（I），减少不必要的会议和打扰。对 agent，RACI 思想可用于"多 agent 任务的责任界定"——每个子任务明确 R（执行 agent）、A（主 agent/用户）、C（挑刺员）、I（用户）。这避免"两个 agent 抢同一块活"或"出了问题没人管"。
【agent 适配度：中】——多 agent 责任界定有用，但 agent 团队规模小，简化即可。

### 28. 风险矩阵（Risk Matrix）
风险矩阵是风险管理标准工具，把风险按"发生概率"和"影响程度"两个维度排成矩阵，通常各分低/中/高三档，形成 9 格。高概率高影响是红色（必须处理），低概率低影响是绿色（可接受），中间是黄色（监控或缓释）。它常配合风险登记册：每个风险记录描述、概率、影响、矩阵等级、应对策略（规避/转移/减轻/接受）、负责人、状态。它的价值是"把模糊的担忧变成可视化的优先级"，避免"凭感觉担心"或"只盯一个风险"。应对策略四选一：规避（不做）、转移（买保险/外包）、减轻（降概率或影响）、接受（留应急储备）。对 agent，风险矩阵适合"动手前把风险摊开排级"——比如采集任务风险：限流（高概率高影响→红色→减轻：单次低频+冷却期暂停自动化）、cookie 失效（中概率高影响→黄色→减轻：每 2 天提醒续期）、机器关机（低概率高影响→黄色→减轻：开机自启）。挑刺员正是干这个的。
【agent 适配度：高】——挑刺员核心工具，动手前排风险优先级。

## 八、创新类（打破常规）

### 29. 设计思维（Design Thinking）
设计思维由 IDEO 的蒂姆·布朗（Tim Brown）和斯坦福 d.school 系统化，源自设计方法论传统。五阶段：Empathize 同理（深入理解用户）、Define 定义（聚焦核心问题）、Ideate 构思（发散方案）、Prototype 原型（快速做粗版）、Test 测试（验证并迭代）。它的哲学是"以人为本、动手思考、快速试错"——先理解真实需求再定义问题，而非先假设问题；用低保真原型快速验证，而非一次性做完美。它强调"发散与收敛交替"：Ideate 阶段不批判只发散，Prototype/Test 阶段收敛验证。对 agent，设计思维适合"产品/界面/交互类任务"——先同理用户真实场景，再定义问题，发散方案后用原型快速验证。它和 PDCA 互补：PDCA 偏改进闭环，设计思维偏创新探索。
【agent 适配度：中】——产品/交互类任务适用；纯工程执行用不上。

### 30. TRIZ（发明问题解决理论）
TRIZ 由苏联发明家根里希·阿奇舒勒（Genrich Altshuller）在 1946 年开创，他分析了数十万件专利，提炼出创新的客观规律。核心发现：技术系统进化有规律可循，创新不是凭灵感而是"消除技术矛盾"。TRIZ 工具包括 40 个发明原理（如分割、抽取、局部质量、不对称、组合等）、矛盾矩阵、物场分析、理想最终结果（IFR）。它的哲学是"别用妥协思维，要消除矛盾"——比如想"爬得快"又想"不触发限流"是矛盾，TRIZ 思路是用原理（如"周期作用""预先作用"）找既快又不限流的方案，而非在快和稳之间妥协。对 agent，TRIZ 偏理论且学习曲线陡，日常用不上；但"消除矛盾而非妥协"的思想对方案设计有启发。
【agent 适配度：低】——理论性强、学习成本高，agent 日常用不上；仅"消除矛盾"思想偶尔可用。

## 九、情境判断类（先判断这是什么事）

### 31. Cynefin 框架
Cynefin 由 IBM 的戴夫·斯诺登（Dave Snowden）在 1999 年提出，用于判断问题属于哪种情境，从而选对应对策略。五个域：Clear 清晰（已知已知，最佳实践，感知-分类-响应）、Complicated 繁杂（已知未知，专家分析，感知-分析-响应，多个好答案）、Complex 复杂（未知未知，涌现，探索-感知-响应，没有现成答案，要试错）、Chaotic 混乱（不可知，紧急行动，行动-感知-响应，先止血再找因）、Confusion 困惑（不知属哪域，先拆分再归类）。它的洞见是"不同情境要用不同方法"——清晰域用流程，繁杂域用专家，复杂域用试验，混乱域用命令。错配会翻车：把复杂问题当清晰问题（套流程）必败。对 agent，Cynefin 是"任务来了先判断情境"的元框架——比如"每日采集"是 Clear/Complicated（有流程有专家），"微信改版导致抓取失败"是 Complex（要探索试错），"线上 D1 灌库报错数据丢了"是 Chaotic（先止血）。判断对情境再选方法，避免用错工具。
【agent 适配度：高】——元框架，先判情境再选方法，治"用错工具"。

## 给 agent 作指导纲要的推荐组合

如果要给 agent 选一套核心指导纲要，推荐这个"五件套"组合：

1. **Cynefin**（先判情境）——任务来了先判断这是 Clear/Complicated/Complex/Chaotic，决定用流程还是试错。
2. **PDCA**（迭代闭环）——已用作 multi-agent-pdca 骨架，强制 Check 环节治盲跑。
3. **六顶思考帽**（多 agent 角色）——白帽=调查员、绿帽+黄帽=规划员、黑帽=挑刺员、蓝帽=主 agent。
4. **5W1H + SMART**（任务澄清）——接任务时把六何问全，目标量化可验收。
5. **风险矩阵 + 5 Whys**（风险与根因）——动手前排风险，撞错时深挖根因别瞎猜。

这五件套覆盖了"判情境→定目标→分角色→排风险→挖根因"全链路，且彼此不重叠、互补，正好契合你 PDCA skill 的设计。
