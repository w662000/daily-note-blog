13:58 · 工作区动态解析 —— 不再把 state dir 钉死在环境变量上
问题：mcp.json 用 env 把 AGENT_TEAMS_WORKSPACE 全局钉死 → 任何会话都操作同一个 state dir
resolveWorkspace() 解析链：--workspace 参数 > AGENT_TEAMS_WORKSPACE > 安全的 cwd > 安装目录。原理：host 每会话起独立 server 进程，各带自己的 cwd → 不钉环境变量即动态。安全过滤：cwd 命中系统/应用目录（Program Files、AppData、System32、node_modules、.codebuddy、.hermes、.workbuddy…）时回落，绝不把团队状态写进系统目录。mcp.json 的 agent-teams 条目删除 env 块。测试 6/6，全量 182/182。

烟测阶段 · 第二个真 bug：信用表有「第三段」—— 真实 fixture 当场暴露
把真实 orchestrator models 输出落盘成 fixture 后立刻发现：真实表是三段，不是两段

第三个真 bug：偶发用例真根因 = taskkill 同步且慢
偶发 not ok 167 等待 26.8s，断言 < 25s 失败
根因不是测试写错，是产品代码：killTree() 用 execFileSync('taskkill',['/PID',pid,'/T','/F'])，而 execFileSync 阻塞事件循环。实测本机：空闲 3251 ms，全量并行负载 ~25 s → 生产后果：成员超时 / reapAll 时 MCP server 事件循环被卡住（HTTP、scheduler tick 全停）。
修法：execFileSync 加 timeout:8000 硬上限（超时回退 process.kill(SIGKILL)）。测试判据改为「子进程睡 60s、上界 30s」。单跑该用例 6.8s（1.2s 定时器 + 3.2s taskkill）。
