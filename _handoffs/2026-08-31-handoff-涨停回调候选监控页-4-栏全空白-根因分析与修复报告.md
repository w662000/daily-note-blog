## 0. 一句话结论

不是数据问题，也不是行情接口问题。是**生成出来的 HTML 里的 JavaScript 有 3 个 bug**，其中 1 个是致命的：`render()` 函数在第 358 行对一个用 `const` 声明的变量重新赋值，抛出 `TypeError` 中断执行，导致后面给 4 个栏位填内容的语句一行都没跑到。持仓面板因为走独立定时器，所以照常显示。

**数据（`CANDS` / `ALLPOOL`）完全是好的，`BROKE` 本来就是空数组——不是 bug。**

## 3. 根因详解

### Bug A（致命，4 栏空白的直接原因）

**位置**：py 第 593 行 + 606 行（产物 htm 第 345 行 + 358 行）

```js
// 593 行：用 const 声明
const card='<div class="stk '+cls+'">'
  + fbTag
  + '<div class="top">…'
  + '</div>';

// 606 行：给同一个 const 重新赋值 → 抛异常
card=card.replace(/<\/div>$/, '<button class="latbtn" onclick="quickLatent(\''+it.sym+'\',…)</button></div>');
```

**浏览器实测报错**：

```
TypeError: Assignment to constant variable.
    at render (涨停回调候选股.htm:358:11)
```

**为什么导致 4 栏全空**：`render()` 里给栏位填内容的语句全在抛错点**之后**：

| 语句 | 行号 | 是否执行 |
|---|---|---|
| `card=card.replace(...)` ← **抛错点** | 358 | ❌ 崩溃 |
| `$('hitGrid').innerHTML = …` | 381 | ❌ 没跑到 |
| `$('watchGrid').innerHTML = …` | 382 | ❌ 没跑到 |
| `$('brokeGrid').innerHTML = …` | 417 | ❌ 没跑到 |
| `$('allGrid').innerHTML = …` | 459 | ❌ 没跑到 |
| `$('lastUpd').innerHTML = …` | 461 | ❌ 没跑到（所以一直显示"未加载"） |

**触发条件**：只要观察池里有**任意一只未突破的票**（走 `else` 分支、需要加"🐣 潜伏买入"按钮），`render()` 必崩。今天 `CANDS` 有 2 只（华天酒店 000428、湖南白银 002716），只要其中 1 只没突破就 100% 复现。

**为什么持仓却正常**：页面底部启动代码两条独立线——

```js
tick(); restartTimer();                        // 拉行情 → render() → 画 4 栏（崩在这条）
renderHold(); setInterval(renderHold, 10000);  // 持仓，独立定时器，不受影响
```

### Bug B（次严重：首屏白等 27 秒）

**位置**：py 第 492 行（产物 htm 第 229 行）

`loadQuotes` 里是按 **3 个参数**调用数据源的：

```js
// 第 540 行附近
const srcs=[[loadTencent,''],[loadEast,'https://push2.eastmoney.com'],[loadEast,'https://push2delay.eastmoney.com']];
fn(codes, host, ok=>{ … });   // ← 传 3 个参数
```

但 `loadTencent` 只声明了 **2 个形参**：

```js
function loadTencent(codes, done){   // ← 只有 2 个
    …
    done(ok && qsSymOk(codes));      // done 实际收到的是 host（空字符串 ''）
}
```

对比 `loadEast` 的签名是对的：`function loadEast(codes, host, done)`。

**后果**：腾讯源**数据其实已经拿到并写入了** `window['v_sz000428']`，但执行 `done(...)` 等于执行 `''(...)`，抛：

```
TypeError: done is not a function
    at s.onload (涨停回调候选股.htm:248:5)
```

异常发生在异步 `onload` 回调里，`settled` 标志永远立不起来 → 每个数据源都要干等 9 秒超时才降级 → 3 个源 = **首屏 27 秒后才渲染**。

### Bug C（隐蔽：显示错误 + 语音播报去重失效）

**位置**：py 第 577 行（产物 htm 第 329 行）

```js
items.push({c:c,name,price,pct,ratio,broke,fb,isNew,vr,volOk});   // ← 没有 sym 字段
```

但下游三处在用 `it.sym`：

| 行号 | 用法 | 后果 |
|---|---|---|
| 347 | `'<span class="code">'+it.sym+'</span>'` | 卡片代码位显示 `undefined` |
| 358 | `quickLatent(\''+it.sym+'\',…)` | "🐣 潜伏买入"按钮传入 `undefined`，一键埋伏失效 |
| 362 | `items.filter(i=>i.broke).map(i=>i.sym)` | `curHits` 装的是 `undefined`，与 367 行 `lastHits.has(c.sym)` 永远对不上 → **突破语音播报去重失效，会反复播报同一只票** |

`quickLatent(code,name,price)` 期望的 `code` 是**纯 6 位代码**（内部会 `mf(h.code)` 加市场前缀），所以这里应补 `c.sym` 而不是 `'v_'+mf(...)+c.sym`。

## 6. 补充建议

1. **同类隐患排查要小心误判**：我用正则扫过 `scan_realtime.py`，命中的 53 条"const 被重新赋值"里**绝大多数是误报**——同名变量在不同 `for` 循环块 / 不同函数里各自 `const` 声明，属于独立的块级作用域，合法。**唯一实测确凿的就是 `card`**。建议用浏览器实测或 `'use strict'` 来验证，别靠静态正则改代码，容易改坏。

2. **加一层兜底更稳**：`render()` 里 4 个 `innerHTML` 赋值是串行的，任何一处抛错后面全废。建议把行情解析那段（遍历 `CANDS`/`ALLPOOL` 的部分）整体包一层 `try/catch`，保证即使某只票数据异常，栏位也能正常渲染出来。

3. **文件名提示**：用户口头说的「涨停回调候选**选股**.htm」在目录里并不存在，实际产物名是「涨停回调候选**股**.htm」。如果 lobsterai 那边记录了别的文件名，建议核对一下生成器的输出路径配置。
