## 三、#7 质量门专论：今天两边各自补了什么

这是唯一在今天发生质变的模块，值得单独拆。

### CF（8 → 8.5）：四项修复，换 0.5 分

| 修复 | 证据 | 为什么只值半个台阶 |
|---|---|---|
| `numberAnchors()` 三处注入 | `util.js` + `test-anchors` 24 断言 | 程序化换算消灭单位错误，但** Tavily 回声未解**：错误声明被检索结果复述时，数字核对仍判"对上" |
| critique-v9：数字复算提为第 1 优先 + severity + 政策断言方向性 | `config.js`；实测 gemma 抓到 v7 绝对抓不到的「6000-7200 篡改成 5000-8000」，标「数字复算/致命」 | severity 让返工从"几乎每题白跑 2 轮"变成只跑该跑的轮——省钱，但不提升单轮质量 |
| compose-v8：禁止把用户数字判"笔误"、税制分税种、禁止断言政策不存在 | `config.js` | 修的是"比不回答更糟"的那类输出 |
| grounding 政策域名白名单 + "政策原文"前缀 + `pctIn` + MAX_CLAIMS 2→3 + 政策插队 | `grounding.js` + `test-policy-claims` 12 断言 | 来源质量与覆盖率都升了；但**模型的中国税制知识本身就是错的**（三次测试三种错法），审核员（gemma）同盲区，产权年限三次没人提 |

**压住分数的四件事**：Tavily 回声、模型税制知识错误、审核员同盲区、**最后版本 `d5cdb747`
未端到端验证**（CF 免费档 10,000 neurons 当日耗尽，报 4006）。
另外答案形态升级后单题成本 251 → **738~806 neurons**，免费档日容量从约 34 题降到约 **12 题**——
质量是用额度换的，这笔账要一直记着。

### 本地（9 → 9）：四项修复，分数不动但性质变了

17:2x 时本地 #7 拿 9/9 靠的是**工程门禁**（git 路径审计 + artifact digest +
`canDeclareDelivery` 列出全部阻塞项），而 CF 唯一超过本地的就是 #7 里的**外部核查**。
今天本地把这一项补上了，且补得比 CF 多两块：

1. **rubric 闭环破除**（CF 没有对应物）：`buildRubricFile` 明示"与 `<original_question>`
   冲突的 acceptance 一律作废——不许当缺陷提、不许拿来判分；照着用户原话做的生产环节是对的"。
   这正对 20261022-YCJBE 的闭环机制：用户「10 万」被改成「10,000」→ 写进 acceptance →
   成员照做 → judge 照判 → **三方一致地错且显示 pass**。
2. **锚点双注入**：生产环节（`buildTaskPrompt`，验收标准之前，契约与锚点冲突时锚点赢）
   和审核环节都有。CF 也是生产+审核双注入，这块打平。
3. Tavily 证据块 + severity/note 分级 + `originalQuestionOf` 取值链，key 已 live 验证
   （3 条政策声明全部命中官方来源）。

**压住"不给更高分"的两件事**：本地 #7 本来就是满分，加分无处可加；新的事实核查层
**只用假 orchestrator 做过集成测试，没用真评审器端到端跑过**——而 CF 的对应层有 3 轮
真模型实战（虽然最后一代也没验证）。这是本地接下来第一件该做的事。

## 六、交叉检查：用户的 P0 硬规则（三角色不共模）

| | 本地 | CF |
|---|---|---|
| 模型异构 | **无自动分配 + 本机凑不齐**：`add_member` 不显式传 `model` 就全员落 `cfg.memberModel`（默认 `deepseek-v4.1-flash`）；系统只给**建议**（`buildModelPlan`："一个模型一个成员，不要重复"，经 `status`/`add_member` 返回）和**警告**（`status` 算"N 个成员只有 M 个不同模型"），分配权在队长、无强制。且**能干活的免费模型本机只有 2 个**：`step-5-preview` 在 `KNOWN_BROKEN_MODELS` 有实证（空 Write 参数、9分07秒、6.8KB 报告 0 字节落盘，"Use it for chat, not for file delivery"），`knownFreeModels()` 过滤后只剩 hy3 + deepseek-v4.1-flash → `buildModelPlan` 输出 degraded 方案。**三个生产成员不共模在本机凑不齐**；第三个异构位置只能给 judge（聊天型，可用 step-5-preview） | **结构强制**：队长 `qwen3-30b-a3b-fp8` / 队员1 `gpt-oss-120b` / 队员2 `gemma-4-26b-a4b-it`，角色与模型绑定写在 `config.js`，改模型要改代码 |
| prompt 异构 | 成员 persona 可配，但生产/审核 prompt 同源同立场 | extract（事实提取）/ critique（对抗挑刺）/ compose（汇总仲裁）三种立场，且 critique 的 prompt 设计目标就是"挑出生产者的错" |
| 实测记录 | 17:2x 跑团队时队长显式指派了不同模型（m1=hy3 / m3=deepseek）——**靠队长自觉达成，不是系统保证** | 一直在结构里 |

**结论**：CF 把用户的硬规则做成了结构；本地把它做成了“建议 + 警告 + 队长自觉”，且本机免费池
对生产成员只有 2 个可用模型，**硬规则在当前账号条件下无法完整满足**（第三个位置只能是
聊天型的 judge）。本地要接近结构保证，需：① `buildModelPlan` 从建议升级为 `add_member`
自动轮询分配；② 第三个家族要么等 `step-5-preview` 修复文件交付，要么引入计费/自定义模型。
