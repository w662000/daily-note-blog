- **ZSHSL 的分母必须是自由流通股本 FINANCE(46)，不能用普通流通股本。**用错分母会系统性漏选高自由流通的小盘股——今天 48 只里漏了 29 只，就是这一个原因。

- **`tdx_screener` 只能当数据源，不能当选股引擎。**四道硬限制已实证：不执行公式语法、不认自定义指标概念、候选集不全、对标准概念表述极度敏感。要精确结果只能靠本地 TDX 公式引擎，或在有行情权限的机器上用 Python 重实现。
- **`tdx_kline` 的 `fHSL` 字段是可靠的当日换手率**（已三处交叉验证 = 成交量 ÷ 流通股本），可以直接拿来复算。

### 技术选型 / 环境约束

- **WorkBuddy 出厂强制流式**，配置层不需要也不应该加 `stream` 字段。用户据此决定「不改动」。
- **Hermes 升级走 pip 路线**（`hermes update` 因安装方式误标 docker 而不适用）。升级前必须全量备份 `.hermes/`。
- **本沙箱的网络限制已摸清**：东方财富系（`push2his` / `push2.eastmoney.com`）被封、TDX 行情服务器 TCP 出网被拦、pytdx 直连主站被防火墙挡、akshare 走系统代理报 ProxyError。**可用的是新浪源 + `trust_env=False` 直连**，这是今天下 5535 只全市场日线的关键。
- **托管 pip 装包要开沙箱豁免**：默认 safe-delete 进回收站，沙箱没回收站会直接 `SAFE_DELETE_FAIL_CLOSED` 中止。

### 安全注意事项

- **本机 Windows 防火墙三档全关**（域/专用/公用），所有 `0.0.0.0` 端口对局域网真实可达。这是今天最高优先级的安全发现，但**防火墙全局变更会影响现有局域网互访，未经确认没有代为执行**。
- **第三方 skill 要扫再用**：`china-stock-data` 里藏着硬编码 token + 非官方域名重定向。即使 token 有效，数据也经过不可信第三方代理、来源不可验证。修复动作属于「重写安装产物」，是在用户明确授权后才执行的。
- 系统级工具（`sc.exe` / 注册表 / `dism`）在沙箱里被安全策略拦截，端口关闭这类操作只能交付精确步骤给用户在本机执行。

### 方法论

- **遇到陌生错误先查官方文档，别凭经验硬猜。**今天 FINANCE(42) 错译连累三轮返工，就是没先查文档的代价。
- **写长文档先搭骨架再分段填充**，避免一次性写入被静默截断（本总结即用此法）。
- **温和测试原则贯彻良好**：Tushare token 探测单次 + 间隔 3s、akshare-one-mcp 验证单次、tdx-connector 分批并行，全天**未触发任何限流**。
