### 5. 模型测速雷达：启动器修了两轮，终于双击就能开

- **第一轮根因**：`start.bat` 用 `pythonw.exe` 拉守护进程，在 WorkBuddy 隔离 Python 环境下**静默崩溃**（无控制台句柄初始化失败），而 bat 又把错误信息吞了，所以表现为"双击没反应还查不出原因"。改回普通 `python.exe` + `start /min`，并把 stderr 落盘。

- **写 bat 的两条红线**：① 回显尽量纯 ASCII，或文件存 GBK/ANSI，别指望 `chcp 65001` 救 UTF-8 无 BOM 的中文；② 起 Python 守护进程用普通 `python.exe`，别用 `pythonw`。
- **后续反转**：下午用户明确要"去掉黑框"，于是又改回 `pythonw` 无窗口模式（这次是从 PY 路径推导 pythonw 同目录路径 + 兜底），14:24 用户实测通过、雷达在跑且无黑框。

### 14. 新建 skill：zlib-book-downloader（全天最硬的一场技术攻坚）

**定位**：按书名自动从 z-library 下载电子书，作为「仓颉拆书」skill 的前置。

- **需求 1**：搭出 skill 骨架——主下载脚本（搜索 → 最佳匹配 → 提取下载链 → 流式落盘）、镜像探活脚本、笔记文档、配置模板。
- **需求 2**：断点续传 + 多线程分块下载，5→4→3→2→1 自动降级，不支持 Range 就退单线程。
- **需求 3**：支持书名 + 作者搜索，按标题相似度 + 作者加分 + 格式偏好排序。
- **需求 4 + 用户中途改需求**：**格式优先级改为 EPUB > TXT，不下载 PDF**。原因很实在——仓颉吃的是文本，PDF 抽文本/OCR 太麻烦，EPUB 解压就能抽、TXT 直通最简单。相应把转换脚本整体重写（去掉 PDF 路径），命中 PDF 结果直接换下一个镜像。
- **一个教科书级的 bug**：`is_cloudflare_challenge` 第一行写了 `if not resp: return False`，踩了 requests 的 `Response.__bool__` 坑——它返回的是 `self.ok`，状态码 ≥400 时为 False。而 Cloudflare 挑战页正好是 503，**导致函数在检测之前就返回了 False**。三处 `if not resp` 全改成 `if resp is None` 才解决。
- **过防方案演进**：原本想抓 `cf_clearance` cookie 回喂 requests，**行不通**——目标站的挑战是源站自有 JS（种 cookie 后自刷新），不发放可复用通行证，而且首页不触发挑战，只开首页会"假通过"。换成**让浏览器直接把目标页 HTML 取回来**交给 Python 解析，绕开 cookie 复用。
- **适配新版页面结构**：搜索结果现在在 `<z-bookcard>` Web Component 里而不是 `<a>` 标签，关键属性是 `href`/`download`/`extension`/`slot`。重写解析逻辑，优先读 `<z-bookcard>` 自带的 download 属性，省掉爬书页那一步。
- **真实下载跑通**：以《把时间当作朋友》端到端验证，最终通过浏览器直接下载拿到 3731 KB 的 EPUB。
- **踩坑四连**：① `/dl/` 下载页自己也挂 Cloudflare（503）；② Playwright 1.62 没有 `waitForDownload`，得用 `waitForEvent('download')`，且 `/dl/` 是官方 Turnstile 挑战、更慢；③ headless 模式 SSL 校验更严，得加 `ignoreHTTPSErrors`；④ 首次访问会扔"1 小时后再试"的错误页，**立即 reload 就好**。
- **按《Playwright 反爬问题与替代方案汇总》文档做了优化**：集成 curl_cffi（模拟 Edge JA3 指纹）进回退链；实现 CDP 模式连接本地已开的 Edge 继承真实指纹/Cookie；加 `--cdp` 参数和一键启动 Edge 的 bat。**最终回退链**：requests 多线程/单线程 → curl_cffi → Playwright launch 模式 → Playwright CDP 模式。
- **收尾决策**：放弃"下载后自动塞进仓颉输入队列"的设想（仓颉本来就靠用户口头给路径启动），改为下载完打印一行 `[next] 蒸馏入口` 提示，把 .txt 路径口头交过去即可。

### 技术侧注意事项

- **写 Windows bat**：回显尽量纯 ASCII，或文件存 GBK/ANSI 无 BOM；别指望 `chcp 65001` 救 UTF-8 无 BOM 的中文（乱码撞到语法字符会导致整行解析失败、后续命令全不执行）。
- **requests 的 `Response.__bool__` 是坑**：它返回 `self.ok`，状态码 ≥400 时为 False。判空必须写 `if resp is None`，写 `if not resp` 会把所有 4xx/5xx 响应当成"没响应"吞掉。
- **判断 Gridea 是否真上线必须查 `output/post/<slug>/`**，只看 `posts/` 有 md 会误判。
- **收件箱空 ≠ 全成功**：它同时兼容"全发完"和"无源可发"，不能作为健康信号。
- **论坛板块不可混用**：每日工作日志走 forum 2/10，handoff 走 forum 3/11。
- **发 handoff 的前提**：项目做完必须在 session 根留 `HANDOFF*.md`，否则夜间扫描视而不见。
- **声称"某脚本会重生脏数据"前**，先核实它是否真被调度系统调用，别把手动一次性脚本说成自动威胁。
- **本环境限制**：wmic 被安全策略禁用、PowerShell 工具异常、netstat 看不到本机端口（命名空间隔离）——排查进程状态改以程序自身日志为权威证据。
