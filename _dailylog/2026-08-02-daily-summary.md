### 1. 模型测速雷达：从「一双击就打不开」修到稳定常驻（上午）

- **修好了 start.bat 双击打不开的老毛病。** 真因不是服务坏了，是启动器设计有三处脆弱点：① 只 sleep 3 秒就拉浏览器，而开机首跑要加载 74 个模型配置 + 336 轮历史，端口还没绑好浏览器就去连，于是"连接被拒绝"；② 用最小化 cmd 窗口挂守护进程，窗口一被关服务就死；③ 端口被占时静默退出，没有任何提示。改法：换 `pythonw.exe` 无窗口后台常驻、启动前先查端口、就绪轮询确认端口真在监听才拉浏览器、全程写 launcher.log。
- **抓到了「第 13 轮测速跑一半没了」的真凶。** 三重实测（端口无人监听 + 进程列表里没有雷达 + 日志停在 11:54 且无报错）确认是进程被外部终止，正是上面「窗口易失」那个根因——用户 11:48 双击的还是修复前的旧 bat。改用无窗口方式手动拉起后恢复。

### 4. SLG 微信采集：定性为「接口已被官方关停」并转向新方案（晚间）

- **用 A 计划派 4 个助手做根因诊断，找出三层问题。** 调度层：定时规则误写成 crontab 五段式被静默降级，实际从没在预定时间跑过。业务层：文章列表接口从 07-29 起全返 0 条。感知层最要命——脚本抓 0 条退出码仍是 0、闸门被空骨架文件绕过、每天重灌旧数据、还有个残留标记文件导致每次都误报「Cookie 已过期」。

### 注意事项（踩坑与经验）

- **调度器有约 5 分钟提前量**，标称 23:00 实际 22:55 起跑，历次稳定。排查时必须换算，排程时可以利用。
- **查自动化配置必须过滤已删除记录**，只看状态字段会把墓碑记录误认为在跑的重复条目——我上一轮就是这么误判的。
- **改代码必须用静态检查工具抓未定义名**，编译检查抓不到运行期的 NameError，07-31 就是这么翻的车。
- **长耗时任务不要依赖后台任务句柄**，会被框架回收；改用系统级常驻 + 日志文件监控进度，并且要做「每步增量落盘」而不是跑完才一次性写。
- **遇到陌生错误码先联网搜清机制再动手。** 这次 SLG 定性完全靠外部证据链闭合，而不是凭经验猜「Cookie 过期」。
- **发请求前走三道离线门禁**：静态检查 → 编译检查 → 零请求路径演练（把目标设为不存在的实体，验证能安全走到发请求前一步）。
- **语雀文档的原始格式不可逆**，改格式字段不会重新触发渲染，只能删除重建。
- **写超长文件内容会静默失败**，正确做法是先写骨架再分段追加，单次控制在约 6000 字符内。
- **读采集结果 JSON 注意字段名**，我曾误读字段导致错判「74 个全部缺失」。
- **云端命令行工具导入大文件有单条 10 万字节硬上限**，必须走批量接口 + 按字节切分。
