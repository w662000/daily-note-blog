## 1. 我们在做什么

做一个「爬 58 同城 → 存云端 → 看板展示」的无锡房产数据系统，分两个独立频道：

- **买房（wx-houseing）**：抓 58「二手房（ershoufang）」频道。
- **租房（wxzf）**：抓 58「租房（zufang）」频道。

整体架构（**务必保留，别改**）：

```
本地 Playwright 无头浏览器爬虫  ──写入──>  local_crawl.db (listings 表)
        │
        │  db_to_sql.py 读 listings → 生成 import_data.sql
        ▼
wrangler d1 execute --remote  ──直连──>  Cloudflare D1  (wx-houseing-db / wxzf-db)
        │
        ▼
Worker (读接口) + Pages 看板 (用户浏览器访问)
```

> 为什么绕这么远：**国内 `*.workers.dev` 的 POST 被网络拦截**，所以爬虫不能直接推 Worker，必须落盘后 `wrangler` 直连 D1。

## 3. 关键认知修正（必读）

**根因**：58 对「沙箱出口 IP」在租房频道做主动验证码墙（code=300），要求浏览器执行 JS 生成新鲜 `fzq_h` 反爬 token。

认知修正（重要）：之前结论"用户浏览器验证救不了沙箱"——**部分错了**：
- **Cookie 粘贴 / 走代理（`127.0.0.1:10808` 对国内 58 是 no-op）仍救不了沙箱 IP**，历史上验证过。
- **但「用户在浏览器里交互式手动过掉验证码」有效！** 手动验证后沙箱爬虫整区 50 页全通、0 撞墙。
- **光猫重启未必换 IP**（CGNAT/共享公网），7-25 上午那次"重启"给的窗口只撑 ~9 页就死；**手动验证才是可靠的刷新方式**。

**续命办法（按可靠性）**：① 首选让用户手动过一次验证码；② 次选重启光猫换 IP。拿到窗口后宽限额度可能很大且不稳定（实测一次手动验证连跑 4 区），耗尽后再刷新（仍优先手动验证）。

## 4. 标准续跑流程（若日后需刷新数据）

每区标准动作：
1. 清本地本区 `listings` 旧数据（**绝不清全表**，否则触发自动播种 liangxi 脏数据）。
2. `USE_PW=1 python crawler.py --district <区code> --no-push` 直跑。
3. `DELETE FROM listings WHERE crawl_batch='seed'`（剔除自动播种残留）。
4. `python db_to_sql.py wxzf/local-crawler wx 58` 生成 `import_data.sql`（只含本区）。
5. 在 D1 **只删该区**的 `price_records` + `listing_snapshots`，再导入。
6. wrangler 查 count 校验。

**严禁**拿到窗口先做 `--test`/探针，会废掉额度。

## 5. 绝对不要再踩的坑（11 条精选）

1. **别用 `--test`/探针消耗宽限额度**。
2. **别死认"浏览器验证救不了沙箱"**——手动验证实测有效；但 Cookie/代理无效。
3. **灌库前必须 DELETE 叶子表**；`import_data.sql` 是普通 INSERT（非 OR IGNORE），重复导入同区会翻倍。
4. **每区前先清本区 `listings`**。
5. **Playwright 实例只启一次**，跨区只 `pw_close_browser()`。
6. **外网命令前必 `env -u HTTP_PROXY ...`** 直连，否则死代理超时。
7. **用 venv 的 python（`$PY`）跑爬虫**（已装 playwright）。
8. **`db_to_sql.py` 丢无小区名房源是正常过滤**。
9. **🆕 清全表会触发自动播种（seed）污染**——用「只删本区」删除；跑完必 `DELETE FROM listings WHERE crawl_batch='seed'`。
10. **Git Bash 没有 `pgrep`**——用 `ps aux | grep crawler.py` 或监测日志大小。
11. **🆕 混合导入会翻倍**——导入前确保本地只含目标区，或删 SQL 涉及的所有区叶子；翻车按 `listing_key` 去重。
